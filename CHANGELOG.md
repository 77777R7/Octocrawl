## Unreleased

- Task verification on every surface (ROADMAP PA item 10, PR 2). The MCP `scrape`, `batch_scrape` and `crawl` tools take `verify`, and a test now keeps their arguments in step with the REST request's keys; `origin` and `parsers` are the two left out. The command line takes `--verify '<json>'`, and its `results.csv` gains a `verification` column. So do the Python client's evidence rows: `passed`, `failed`, `not_requested`, or empty from a server that does not verify. The access task runner (`research/access/run-set.mjs`) sends each task's predicates as its contract. Its record says on how many attempts the product's verification agreed with its own verdict and names any where it did not; `--no-contract` sends none.
- Task verification apart from the fetch status (ROADMAP PA item 10, [ADR 0006](docs/adr/0006-task-verification.md)). Scrape, batch and crawl take a task contract, `verify: { checks, emptyOk? }`, and every answer carries `verification`. It is `passed`; `failed` with a reason (`checks_failed`, `page_not_read`, `empty_not_allowed`) and each check's outcome; or `not_requested` without a contract. `status` stays the fetch's. The check types are the access task runner's, judged the same way: `markdownIncludes`, `markdownMatches`, `markdownCountMin`, `minTables`, `listRecordsMin` and `field`, plus `recordFields`, records that hold every field named. A batch or crawl keeps its contract across a resume, and a page handed to the person is verified again. The Evidence Record gains an optional `verification` block (additive under `w2l.evidence/1`). A hosted server refuses the regular-expression checks. The runner's judgement moved to `research/access/judge.mjs`, which the verifier is tested against on every predicate of the 92 tasks.
- The public site counts Lighthouse and PageSpeed Insights runs as automated: they load the page as an emulated `moto g power (2022)` (a `Moto G (4)` before Lighthouse 10, with `Chrome-Lighthouse` on PageSpeed), which a current Chrome on Android never names, and 15 page events in the 30 days to 2026-10-10 came from them. The operator docs say how a scripted site check carries the `w2l_internal` cookie so it is not counted either. A new `scripts/public-preview/weekly-report.mjs` prints a week's traffic on one page: site visitors by source and page, waitlist sign-ups, hosted API and MCP requests by route, recent distinct scrape and map callers, GitHub, npm and PyPI, and Search Console and Bing when their credentials are set, each source reported as not read rather than zero when it cannot be read.
- A paid provider's step that its session's end cut off is read as that session's timeout when its timer fired a little early. A timer set for a deadline can fire a millisecond or two before the clock reaches it, and the vendor rung then read the session as not yet ended: a CDP connect that gave up at the session's end answered `provider_error` instead of `timeout` (the connect case of `ladderCli.test.ts` failed that way twice in CI). The session's end is now read 25 ms early; the request's own end is read as the ladder reads it.
- A page React streamed (React 18 and 19 server rendering) is read over HTTP as its own scripts put it together: the parts it sent later in `<div hidden id="S:…">` are moved into place, as `$RS` moves a segment into its placeholder and `$RC`/`$RR` replace a boundary's fallback, in the order the page calls them. x.com's posts had sat in hidden parts outside the `<main>` that holds the profile, so the HTTP answer kept the posts without the profile's follower count. A fetch of Wayfair's sofa category (T018) on 2026-10-10, put together, no longer reads as a shell and holds 85 prices by T018's pattern where it held 46. A call that names no part in the page, as on a page a browser already put together, is left alone, and a part whose target is gone (a boundary inside a fallback an earlier call replaced) is removed, as React's calls remove it. Every step the calls take (a node moved or removed, or a parent walked past to see where an element is) is charged to a budget of four steps per element of the page, so the time is linear in the page however its parts nest: pages of 10,000 parts each nested in the next, or each 20 elements deep in the one before, had made the calls take from 3 seconds to over 4 minutes, and now take 20 to 250 ms; a page that spends the budget keeps the parts it did not reach hidden. On 51 real pages (20 of them streamed: x.com, Wayfair, Vinted, nextjs.org, vercel.com, shadcn/ui, shopify.dev) the calls took at most 0.09 steps per element. The extractor is now `extract-tf/21`.

## 0.4.1 — 2026-10-10

The published packages (`octocrawl`, `@octocrawl/cli`, `@octocrawl/sdk`, `@octocrawl/mcp`, `octocrawl-client`) at 0.4.1. It holds 0.4.0 and the fix for a request reset on a kept-alive connection when the server's event loop was held. Polling clients of a crawl met that reset. It also holds two main-content fixes from PA item 4. Products a page lists at the top level of its JSON-LD read as a listing. The page's `<main>` is preferred over chrome around it.

- A client of the local API or the local MCP host no longer has its next request on a kept-alive connection reset (`TypeError: fetch failed`, `read ECONNRESET`). The reset came after the server's work held its event loop for longer than the keep-alive timeout. A crawl's synchronous extraction did that for 5 to 6 s. A crawl's status poll after a mid-run `/pages` read was reset about one run in two (the real-site cases A14, A15 and A31 of the 2026-10-10 regression check). An idle connection is closed at the timeout only when no request has arrived on it; a request that did is answered. The hosted API's server has the same change, which takes effect when hosted Octocrawl is next deployed.
- Products a page declares each on its own at the top level of its JSON-LD, three names or more (Redfin's search results: a script per home), are a listing's cards, not the page's own product. So the page is a listing. Products declared in a section of recommendations are not (a product page's "Customers Also Viewed" cards, each with a script of its own, as on Zappos). Nor is a set one of which the page's h1 names. A product page whose own price follows its title stays one. Read as a product page, Redfin's results had answered with its market trends and two prices.
- A region the article cascade finds outside the page's `<main>`, when every h1 of the page is in that `<main>`, gives way to the `<main>`. Sephora's category page had answered with its header's promotion, its one block of prose. Its `<main>` held the title, the result count and the product tiles. A region that holds the `<main>` and more, one inside it, and one inside a hidden element stay as they are. React streams a page's body hidden outside the `<main>` its script moves it into (x.com). A hidden region is still reported as one (Eurostat's banner). The extractor is now `extract-tf/20`.
- The Blog index (`/blog/`) is laid out like a publication's. It shows the title alone, then a row of category tabs (All Posts, AI Agents, AI Engineering, Web Extraction). Next comes the newest article, large, with its cover, category, byline and date. The others follow as cards that name their category. Each tab is a link to its own page (`/blog/category/<slug>/`, `noindex, follow`), so the tabs work without a script. Each article's registry entry (`apps/public-web/scripts/blogPosts.mjs`) names its category.

## 0.4.0 — 2026-10-10

The published packages (`octocrawl`, `@octocrawl/cli`, `@octocrawl/sdk`, `@octocrawl/mcp`, `octocrawl-client`) at 0.4.0. It holds everything below since 0.3.2 on 2026-10-09. ROADMAP's PA phase names this release once items 3, 7 and 8 have their real-site records; their code shipped in 0.3.1 and 0.3.2.

Highlights:

- A short page that names a refusal or a browser check is judged a block.
- Products a page's JSON-LD collection or `ItemList` declares make it a listing, not a product page.
- A main region the page hides is no longer taken for its content.
- A vendor session that cannot be opened is reported as the provider's failure.
- octocrawl.dev has a Blog, and the docs have new guides.

All changes:

- The docs' Advanced reference matches 0.3.2 again:
  - The REST routes include map and crawl.
  - The Evidence Record lists `my_browser`, `robotsDecision.userOverride` and `overrideBasis` as they are (a server on your computer reads a URL you named although robots.txt disallows it).
  - It also lists `identity.device` and `requestHeaders`, every `access` field with `completion`'s values, the screenshot artifact and the fields optional in the v1 schema.
  - The extractor example is `extract-tf/16`.
  - The error example and the `unsupported_format` row no longer call `html`, `rawHtml` and `screenshot` unsupported.
  - The error table adds `rate_limited`, `quota_exhausted` and `hosted_unavailable`.
- octocrawl.dev has a Blog (`/blog/`), in the top navigation and the footer. The six task guides moved there as articles. Each is rewritten around one search question. Each has a cover, figures rendered from its saved run, a byline and date, Keep reading cards, and `BlogPosting` data. The articles cover Claude Code web scraping, web scraping for RAG, and finding all pages on a website. They also cover scraping a website with login, extracting structured data from a web page, and scraping a list of URLs. Their old `/docs/guides/…/` addresses (and the `index.md` copies) answer 301 with the new one, from the `redirects.json` the docs build writes; the sitemap, llms.txt and llms-full.txt list the articles. The research behind each article (its search brief and the runs it cites) is under `research/blog/`. Amazon.sg product JSON and Monitor to HTTPS Webhook stay in the docs.
- The public site's page events and preview outcomes leave out more traffic that is not a visitor. `automated` is now also true for strings scanners forge (a Safari token cut to `Safari/537.3`, EdgeHTML's `Edge/`, Firefox before 115, the one Chrome build `117.0.5938.132`), which sent 14 of the 132 page-event beacons from 2026-10-07 to 2026-10-09. A new `internal: true` marks the operator's own browser. It is set by opening any page with `?internal=1` (an HttpOnly `w2l_internal` cookie; `?internal=0` clears it). It also marks the browser built into the Claude desktop app (`Claude/<version>` in its user agent), where site checks run; it sent another 14. The privacy page and the log query in `docs/public-preview.md` say so.
- A vendor rung whose session cannot be opened is the provider's failure, as a failure during the vendor's fetch already was. That is when its session API is down, or hung past the vendor API's 30 s cap. The result is `failed`/`provider_error`, with a `provider_failed` trace event and the vendor's key kept out of its message. A session that runs out its tariff's time before the request's own deadline is the provider's `timeout`, as one during the page's navigation was. That covers its CDP connect, its User-Agent probe or the robots.txt fetch. The request's own deadline or a cancel is still the ladder's to answer. The ladder goes on to its next rung or answers with that failure, and the call stays on the record charged at its ceiling. Before, the error escaped the rung, and the API answered 500 with no record of the page or the call. That happened once in each of three PA 4 Steel runs. It came at about 32 s, after the local rungs had been refused within about 2 s. The server now also logs every unexpected error, a local server included, which answers with the error's message but had logged nothing.
- The docs have a Scrape pages to Markdown for RAG guide (`/docs/guides/rag-markdown/`). It covers:
  - one page through hosted Octocrawl (a real read of the Python `json` docs, its tables and Evidence Record)
  - what the Markdown keeps and drops
  - many pages with `map` and `batch --out`
  - a Python script that turns a batch into chunks that keep their source URL, fetch time and Markdown hash (run on 2026-10-09)
  - why to deduplicate on `outputSha256.markdown` and not `rawSha256`
  - filtering on `status`
- The docs have a Give Claude Code web access guide (`/docs/guides/claude-code-web-access/`), and Connect MCP links to it. It covers:
  - adding hosted Octocrawl in one command and its scopes
  - a real Claude Code 2.1.295 task from 2026-10-09 (two `map` searches, one `scrape`, an answer citing the Evidence Record's final URL and fetch time)
  - how to ask for what you need back
  - the local server for everything else
  - what to check when it does not work
- Products a page declares under its `CollectionPage` or `SearchResultsPage` node are the collection's, as those in an `ItemList` already were, so such a page is a listing, not a product page. eBay's category pages list their listings as the collection's `about.offers.itemOffered`. Read as a product page, the answer from Steel's page in the PA 4 runs was the brand list with two prices. A region the page marks `role="main"` is now taken for its content as a `<main>` is. That applies when the region holds at least half of the page's text blocks and every h1 of the page. So eBay's site header and a government site's banner stay out. A Stack Exchange question, whose h1 sits above its `role="main"`, keeps its title. An `<article>` or a `<main>` still comes first. The extractor is now `extract-tf/19`.
- A page whose own top-level JSON-LD `ItemList` lists three or more products is a listing, as one inside a `CollectionPage` already was. So its grid of products is its content. H&M's category pages declare no `CollectionPage`. They had been read as a product page and answered with their category blurb. A list named for recommendations ("You may also like") and a page whose first h1 is followed by a price of its own, outside the listed products' cards, stay product pages. The extractor is now `extract-tf/18`.
- The HTTP rung offers two more script-filled pages to the browser rung (`client_rendered_suspected`), both of which had answered `success` with headers and no figures:
  - **`loading_text`**: a page of at most 4,000 visible characters whose extracted region still says it is loading, beside its scripts (WSJ's market data). The message is an element's whole text with its ellipsis ("Loading...", "Fetching quotes…"), or "Please wait"; a button's or a link's text, and text inside `hidden`, `aria-hidden="true"` or a screen-reader-only class, do not count.
  - **`hydration_shell`**: a thin page whose state is a bare lower-case `window.__data =` or `window.__state =`, as `window.__STATE__ =` already was (the World Bank's indicator pages). Longer lower- and camel-case names (`window.__staticRouterHydrationData`, Chartbeat's `window._sf_async_config`) are not page state.
- The docs have a Use your own Chrome guide (`/docs/guides/own-chrome/`). It sets the `my-browser` lane, handoff and saved logins side by side. It covers what to click in Chrome and a real read of a signed-in page from 2026-10-09 (and the first try that timed out). It also covers what Octocrawl never does, and what each unfinished result means. The top navigation's Your own Chrome entry leads to it instead of the home page, and the reference names 0.3.2 as the published SDK and Python client.
- A short 2xx page led by a heading that names a refusal or a browser check is a block, on every lane, whether or not it was read as content. Either sign makes it a block. One is a refusal outright in a heading or the title ("Pardon Our Interruption", "Robot or human?"; a `captcha` when the page asks a person to press and hold). The other is two signs of a check in its shown text, one of them in a heading (eBay's "Checking your browser before you access eBay" … "Please wait", which had answered `success`). Pages asking for JavaScript are shells, not walls, and prose quoting such words is not a heading. The words are read in what the page shows, not its scripts.
- A main region the page hides (the `hidden` attribute on it or around it) is not the page's content: the page is `failed`/`empty_unverified` with the whole page as evidence, and the http lane asks for the browser. Eurostat's data browser read in a browser had answered `success` with the EU banner's hidden dropdown. A section hidden until a reader's search finds it (`hidden="until-found"`) stays content. So does a part React streams hidden before its script moves it into place (`<div hidden id="S:…">`, or inside a table `<table hidden>` around a `<tbody>`, `<tr>` or `<colgroup>` with that id). So does a page a modal marks `aria-hidden`. The extractor is now `extract-tf/17`.

## 0.3.2 — 2026-10-09

The published packages (`octocrawl`, `@octocrawl/cli`, `@octocrawl/sdk`, `@octocrawl/mcp`, `octocrawl-client`) at 0.3.2. It holds everything below since 0.3.1 on 2026-10-06.

Highlights:

- The `my-browser` lane reads a page in your own Chrome, on the sites you allow (`--lane my-browser`, `"access": "my-browser"`).
- A list that stopped at a check continues in your Chrome.
- Paid provider calls run under a price ceiling and a spend ledger, and each one is on the page's Evidence Record (`access.paidCalls`).
- More refusals and loading pages are recognised, and the ladder escalates on more failures.
- The package pages point at octocrawl.dev.

All changes:

- Two more refusals of automated visitors are recognised as blocks (`blocked`/`bot_detected_generic`) when a site answers them with a 2xx. This holds on every lane and whether or not the page was read as content. On a page not read as content, a captcha or a login form names the gate first. The first refusal is a short page carrying Akamai's reference to the refused request ("Reference #18.…", "Incident Number: 18.…"). The second is a short page whose heading reports unusual or suspicious activity and whose copy refuses automated traffic. Short means at most 1,500 characters of visible text, so an article quoting either stays content. The whole body is read in one linear pass that stops at that bound, since such a wall can sit past 120 KB of scripts. Akamai's error pages, which carry the same reference with a 4xx or 5xx, stay `failed`. In the PA 4 Steel runs Autotrader's Akamai page and Nordstrom's wall had answered `success`.
- The docs have a Map a site guide (`/docs/guides/map-site/`). It covers mapping without an account (REST, MCP, CLI, SDKs) and a real answer from 2026-10-09 explained field by field. It also covers the options that narrow the list, and what a short or empty list means. The top navigation's Map a site entry leads to it instead of the reference. Each navigation entry's parts are separated by spaces, so its link text reads as words ("▤ Scrape a page Markdown, …") rather than run together. An option name in a docs table's first column no longer breaks mid-word.
- A page whose article region only names it has no main content. It is `failed`/`empty_unverified` with the whole page kept as evidence, on every lane, instead of `success` with a heading for its content. A region only names the page when its headings hold fewer than 100 characters, and it has fewer than 3 characters and no image beside them. A canvas or a video leaves nothing in the Markdown, so it does not count. In-page jump links such as "Skip to Filters" are set aside. List, table and product regions, which are short or heading-led by design, are not judged so. In the PA 4 Steel run the Tesla inventory page, loaded with no vehicles, had answered `success` with "Don't see the Tesla you're looking for?". The extractor is now `extract-tf/16`, so pages cached under an earlier version are fetched again.
- Hosted Octocrawl publishes an MCP server card at `/.well-known/mcp/server-card.json` (on `mcp.octocrawl.dev` and `api.octocrawl.dev`), the format Smithery reads when it lists a server: name, version, that no sign-in is needed, and the three tools `/mcp` offers, from the same definitions. Any other `/.well-known` file is 404 instead of 403 `hosted_unavailable`, so a client probing for OAuth metadata is not told it was refused.
- octocrawl.dev has one top navigation on every page (`apps/public-web/scripts/siteNav.mjs`). Its entries are Product, Docs, Free tiers and Changelog, with GitHub and Try it beside them. Product holds what Octocrawl does, the ways to use it, and connecting an agent over MCP in one line. Docs holds the guide and reference pages. The menus are `<details>`, so they open without a script; `docs-assets/nav.js` adds hover, one menu at a time, Escape and, on narrow screens, a Menu button. A menu prints open in the site's glyph style. The card appears a text line at a time under a dotted print head, its entries in turn, and its monospaced words decode from noise. With reduced motion it opens at once. The new Changelog page (`/changelog/`) is built from `CHANGELOG.md`, its links to repository files pointing at GitHub, and is in the sitemap and llms.txt; `.gcloudignore` lets `CHANGELOG.md` into the Cloud Build upload.
- A page with little text (at most 4,000 characters) that still shows its data is on the way is waited for up to 8 s in all, on the browser rung and on a provider's. The signs are a visible element marked `aria-busy`, or a visible short "Loading…" or "Fetching results..." text, not on a button or a link.
