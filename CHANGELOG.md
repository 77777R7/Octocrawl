## Unreleased

- **JSON fields from what scholarly and news pages declare.** A JSON schema's `title` takes a page's `citation_title` before its first heading, so arXiv's abstract page no longer answers `Computer Science > Computation and Language` for its title. `description` takes `<meta name="description">`. A key no label covers is matched to the page's `citation_*` tags and its schema.org article JSON-LD (`headline`, `name`, `datePublished`, `dateModified`, `description`) by name, and `author`/`authors`, `doi`, `date`/`publicationDate` and `headline` to the tags that state them; a repeated tag fills an array but never one string, and articles that disagree leave the field out as `field_ambiguous`. Table rows labelled by a data cell ending in a colon (Wikipedia's taxobox `Kingdom:`, arXiv's `Cite as:`) are labels, and a line break in a value reads as a space. Wikipedia's cladograms (`table.clade`) are no longer given as data tables in `tables` or GFM tables in Markdown. ([docs/json-extraction.md](docs/json-extraction.md))

## 0.6.0 — 2026-10-17

The published packages at 0.6.0. It holds the five MCP changes below; the REST API, the SDK, the CLI's commands and the Python client are unchanged apart from their versions. It is a minor version because one change is visible to programs: a tool call that fails now answers with an `isError: true` result instead of a JSON-RPC error, so a script that caught the rejected request gets a result. The exported `callTool` still throws. Clients that worked with 0.5.0 keep working: a 2025-era client is served as before, and clients that ignore `instructions`, titles and hints see no change; the order of the exported `TOOLS` and `TOOL_NAMES` changed. On the hosted service, MCP 2026-07-28 is live on `/mcp` and `/mcp-oauth` since 2026-10-17 (revision `h19mcpv2`); the other four changes reach the hosted tools at its next deploy.

- **MCP tool errors the model can act on.** A tool call that did not run now answers as a tool result with `isError: true` instead of a JSON-RPC error, which clients may hide from the model. The text's first line is `<code>: <message>` (the API's code and message, not the raw response). A `Retry after N s` line follows when the server said how long to wait, then one `Next: …` line for each `agentHints` entry, without campaign tags. `_meta['octocrawl/error']` carries `{ code, status }`. Three cases get their own text: a local API that is not running gives `api_unreachable` and says how to start it (the stdio server also says so once on stderr at start); an unknown crawl or batch id gives `not_found` with the next step; a tool a deployment leaves out stays a protocol error and now names the tools it offers. A cancelled call stays a cancellation, over stdio too. A program that caught the rejected `callTool` promise now gets the result instead. The exported `callTool` still throws. (docs/mcp-client-ux-tasks.md W5)
- **Hosted MCP lists only what hosted Octocrawl serves.** The hosted `scrape` schema no longer offers what the hosted server refuses: `actions`, `robotsOverride`, `lane`, `handoff`, `skipTlsVerification`, `access`, and the regular-expression `verify` checks. It also drops what it takes but cannot honour. On hosted, `mode: authed` read anonymously, since there are no saved logins, and `lockdown`, `storeInCache`, `maxAge` and `minAge` had nothing to act on, since hosted caches nothing. A keyless connection also loses `screenshot` and `waitFor`, which need the browser lane. `map` drops `ignoreRobotsTxt` and states its hosted caps (limit 5,000, timeout 60 s). A hosted MCP scrape now stops at 100 s by default and at most (REST keeps 300 s), under claude.ai's 240 s tool limit. The keyless `tools/list` goes from 24,337 to 16,135 characters. A client that still sends a removed option gets the same refusal as before. (docs/mcp-client-ux-tasks.md W6)
- MCP 2026-07-28 on every Octocrawl MCP server (`@octocrawl/mcp` over stdio, the local MCP host, and `/mcp` and `/mcp-oauth`): a client that opens with `server/discover` is served without a session, and a 2025-era client that opens with `initialize` is served as before. A request naming a revision the server does not serve is answered 400 with the spec's `UnsupportedProtocolVersionError` (-32022), listing the revisions it does serve. The MCP servers now run on the v2 MCP TypeScript SDK (`@modelcontextprotocol/server`).
- **MCP `instructions` and identity.** `initialize` now answers with `instructions`: what Octocrawl does, which tool a task starts with, how to read a result (`status`, `verification.status`, `readiness`, `agentHints`), and what the connection can reach. They are written from the tools that surface lists: a local server, hosted keyless, hosted with a key, or `/mcp-oauth`. `serverInfo` adds `title` `Octocrawl`, a `description` and a `websiteUrl`; the hosted server card and `server.json` carry the same title and description. Clients that do not read `instructions` see no change. (docs/mcp-client-ux-tasks.md W3)
- **MCP tool titles and honest hints.** Every one of the 38 tools now has a plain `title`, the same in `annotations.title`, and all four hints set explicitly. The 19 reads are `readOnlyHint: true`. Cancels, `remove_login`, `import_login` (it replaces the login already saved for that domain) and `pause_monitor` are `destructiveHint: true`. The local `scrape` stays not read-only, since its actions and authed mode act as the person; the hosted copies are read-only. A client that asked before every call because hints were missing (the spec's defaults) can now let reads through. `tools/list` puts the general tools first (`scrape`, `map`, `get_scrape`, then crawl and batch), so the exported `TOOLS` and `TOOL_NAMES` change order. `import_login` carries `anthropic/requiresUserInteraction`, and the hosted tools carry ChatGPT status lines in `_meta`, which `/mcp-oauth` now merges with its `securitySchemes` instead of replacing them. (docs/mcp-client-ux-tasks.md W4)

## 0.5.0 — 2026-10-17

The published packages (`octocrawl`, `@octocrawl/cli`, `@octocrawl/sdk`, `@octocrawl/mcp`, `@octocrawl/ai-sdk`, `octocrawl-client`) at 0.5.0. It holds everything below since 0.4.2 on 2026-10-13. It is a minor version because one change refuses requests 0.4.2 accepted: a task contract that checks Markdown, sent with explicit `formats` that leave Markdown out, is now refused before fetching. Entries about the hosted service (api. and mcp.octocrawl.dev) and octocrawl.dev describe what is already live there. The Python client is unchanged apart from its version.

Highlights:

- **MCP sign-in by OAuth** (hosted, already live). `https://mcp.octocrawl.dev/mcp-oauth` serves the same tools as `/mcp` to clients that sign in to an Octocrawl account instead of sending a key. Claude Code, claude.ai, ChatGPT and Cursor were each connected and recorded on 2026-10-16. The MCP Registry entry (`server.json`) lists it as a second remote from this release.
- **Task verification:** a new `tableRowsMin` check (`verify/2`); batch and crawl contracts judged on the data they deliver; the AI SDK's `scrape` tool takes `verify` and returns `verification` and `readiness`.
- **Explicit lists:** an `itemSelector` now chooses the items for Markdown, HTML, tables and JSON alike.
- **Access:** the `installed_chrome` route, with a challenge wait. Pages DataDome or Cloudflare let through are no longer read as blocks, and a site's own captcha or DataDome's is judged `captcha`.
- **Extraction:** `extract-tf/28`. Two sibling video cards without prose are content, which TikTok-style feeds needed.

All changes:

- MCP connections by OAuth (ROADMAP PH item 6; hosted and octocrawl.dev, already live).
  - `POST https://mcp.octocrawl.dev/mcp-oauth` answers a call without a valid access token with 401 and Protected Resource Metadata (RFC 9728) at `/.well-known/oauth-protected-resource/mcp-oauth`.
  - octocrawl.dev is the authorization server: OAuth 2.1 with PKCE S256 only, public clients, Client ID Metadata Documents or dynamic registration, and `iss` in every answer.
  - The consent page names the client, the host it returns to and the account's credits left. Access tokens last an hour and are bound to `/mcp-oauth`; refresh tokens rotate, and one used twice ends the connection.
  - Each connection is an account key of its own: its calls spend the account's credits and show under its name in Activity. It does not count against the five keys; an account holds at most ten connections. API keys lists them, and Disconnect ends one. Its next tool call gets 401 at once, so the client asks to sign in again. A connection also ends after 90 days unused.
  - `/mcp` is unchanged: keyless within a daily allowance, or a key.
  - The dashboard's Connect page leads each coding agent with the sign-in setup and folds the key setup under "Use an API key instead"; Connect MCP gains a sign-in section.
  - `server.json` lists `https://mcp.octocrawl.dev/mcp-oauth` as a second remote, so the MCP Registry shows it from this release.
- Verification: a `tableRowsMin {tableIndex, columns, min}` check counts the data rows of a delivered table (`formats` must include `tables`) whose required columns all hold a letter or number. `minTables` still counts tables only. The verifier is now `verify/2`.
- Verification: a batch's or crawl's page contract is judged on the data the page delivers, after the requested formats are applied. Before, a check could pass on a field (such as `document.title`) that the published page left out.
- An explicit list's JSON is built from the selected records. Before, the plain `json` format or a custom schema could fill a different, page-level product and mark it complete while Markdown and `list.records` held the selected ones. Missing or ambiguous values stay incomplete.
- The AI SDK's `scrape` tool takes the optional `verify` contract and returns `verification` and `readiness`, which it used to drop.
- A DataDome page whose iframe is its captcha is judged `captcha` even when its response headers alone would have named a generic block. A person can then be offered the page (handoff); a device check still is not.
- Extraction: a page whose heading-less main region holds two sibling article cards of one template, each with a sourced video and linked text, is now read as those cards instead of coming back empty. Ordinary pairs, duplicates, unsourced videos, navigation and carousels do not qualify. The extractor is now `extract-tf/28` (27 came with the explicit list items below).
- Access trace: `ladder_channel_started` says how much of the run's time a rung had when it started, `ladder_channel_not_served` says why a rung was left out (a screenshot request, for example, leaves out `installed_chrome`), and an `egress_proxy_refused` warning says when the egress proxy itself refused (402, 403 or 407) rather than the site. A run that succeeds behaves as before.
- Browser lane: the region wait judges a contract's Markdown checks on the main content the answer will hold, not on the whole live page, so content outside it no longer ends the wait early; it judges the read the wait would end on, up to 1 MB. A screen-reader "loading" placeholder below the screen no longer stops the wait.
- Hosted Octocrawl's scrape tool description no longer names `get_scrape`, which hosted Octocrawl does not serve.
- Hosted Octocrawl: a scrape read over HTTP alone because the caller has no browser lane (no key, a key without the browser lane, or an account with fewer than five credits) now says that, and what opens the browser lane, instead of `retry without fastMode`, which the gate would have pinned again. A caller that sent `fastMode: false` is told it was not honoured.
- Hosted Octocrawl: the stored scrape record (`GET /v1/scrapes/:id`, the MCP `get_scrape` tool) now carries the same hint as the scrape's answer, not `retry without fastMode`.
- A single-page list request with an explicit `itemSelector` now chooses those items for Markdown, HTML and tables, rather than a neighbouring article or the whole page. An explicit region still takes precedence, and explicit list records respect region exclusions; original record positions and base URLs are retained. Whole-page requests, auto-detected lists and pagination keep their content-selection behaviour.

- A captcha page a site serves itself is now judged `captcha`, not `bot_detected_generic`. A page counts as one when it has both:
  - its own widget script, on a `/captcha/` path;
  - an ask to prove the visitor is human.

  For example, studylib.net's "Security Check", seen after Cloudflare's challenge clears. The page needs a person, so a local server can now offer it to one (handoff) rather than report a generic block. Whether a task passes does not change.

- A contract that checks Markdown now requires explicit response formats to include it; conflicting scrape, batch and crawl requests are rejected before fetching or creating a job. When formats are omitted, a compact adapter response includes the checked Markdown beside its default JSON. `passed` still means only that the configured checks passed, not independent field accuracy.

- A page DataDome or Cloudflare let through is no longer read as a block.
  - DataDome sends `x-datadome: protected` on every page of a site it guards, the pages it lets through included. That header alone now names a block only on an answer that is not a success. DataDome's real block (a 403 with `x-datadome-cid` and `x-dd-b`) and its interstitial and captcha pages are still caught.
  - Cloudflare's `precursor` script, which it serves on the page past its challenge, no longer counts as a challenge, the same as its `jsd` script already did.
  - This affects every lane. On the full 92-task set, main verified 43 and this change 42; the real-site batch L was 12/12 on both. The tasks that differ are explained in the [acceptance record](research/access/runs/2026-10-14-installed-chrome-acceptance-7b56397b.md).
- The `installed_chrome` acceptance on the 16 challenge tasks:
  - The final commit verified 11 and 7 in two runs, and the commit before it 11 and 9. The probe the route was built from verified 12 and 12. As merged, before the fixes here, the rung verified 2.
  - In the run of 7, the four tasks it lost all showed the sites' real 403 challenge after the full wait.
  - [Record](research/access/runs/2026-10-14-installed-chrome-acceptance-7b56397b.md).
- The `installed_chrome` rung waits for a check that clears itself, as the route was measured. A page with decisive challenge evidence (a vendor's challenge header or plumbing, its widget, a wall) is re-read once a second for up to 20 s and never clicked, and the page it gives way to is read. A page that only loads a captcha script for a form is not waited on. Before this, the rung answered `blocked` as soon as it saw the challenge, which the probe it was built from never did. The trace event `challenge_wait` records the outcome.

- The `installed_chrome` access route (ADR 0005, enhanced). A grant that names `installed_chrome` adds a rung after the browser lane for requests with `access: "enhanced"`.
  - **The launch.** The rung launches the Google Chrome installed on the machine the way it was measured to get through checks the bundled Chromium did not: headed, a fresh temporary profile per page, and the DevTools port on `127.0.0.1`, closed to pages.
  - **How it reads.** Playwright drives that Chrome over CDP and reads in Chrome's own window with Chrome's own identity.
  - **Where it applies.** It is for a local server only, in standard mode. It never takes `actions`, screenshots, `mobile`, custom headers or `skipTlsVerification`.
  - **Limits.** At most two windows are open at once. A proxy that needs a login is refused.
  - **When Chrome is missing.** The answer says so with a `browser_not_installed` warning that names where to get it, or `W2L_CHROME_PATH`.
  - **On the record.** Evidence Records name the route `installed_chrome`, with Chrome's version and the launch's flag set.
  - **The measurement behind it.** With Playwright over CDP, Chrome held 12 of the 16 challenge tasks in each of two runs, against 12 and 13 over raw CDP with the same launch ([record](research/access/runs/2026-10-14-library-probe-pwcdp.md)).
  - **Still to come.** The product's own acceptance runs.

- Passwordless WebAuthn login pages and image object-count verification pages can now be named `login_wall` and `captcha` when their final URL, primary heading and actual controls agree, including controls beyond the first 64 KB. The added scan is bounded and does not override a page already judged contentful. This changes failure classification, not task completion.

## 0.4.2 — 2026-10-13

The published packages (`octocrawl`, `@octocrawl/cli`, `@octocrawl/sdk`, `@octocrawl/mcp`, `@octocrawl/ai-sdk`, `octocrawl-client`) at 0.4.2. It holds everything below since 0.4.1 on 2026-10-10. Entries about the hosted service (api. and mcp.octocrawl.dev) and octocrawl.dev describe what is already live there; the packages' own changes are the extraction, verification, readiness and browser-lane ones.

- A browser lane that cannot start because no browser is installed now says so (ROADMAP P1, one-line install). On a clean machine without `npx playwright install chromium`, a page that fills its data with JavaScript came back from `npx octocrawl@0.4.1 scrape` as `failed`/`empty_unverified` with hints that "the browser lane was tried" and to retry "with the browser lane available", and no word of the missing browser. Playwright's "Executable doesn't exist" now adds `browser_unavailable` to the browser rung's trace, the answer carries a `browser_not_installed` warning, and its first hint is to run `npx playwright install chromium` once (`npx patchright install chromium` under `W2L_BROWSER_ENGINE=patchright`, whose browser is its own build). The failure reason stays `connection_error`. The page cache stores a result without that warning, so a hit after the browser was installed does not ask for it again.
- Hosted Octocrawl: a key runs one scrape at a time that may use the browser lane, a revoked key stops at its next start, and every key's start is logged per key and day (ROADMAP PH items 1 and 2). A second such scrape with the same key is `429 browser_busy` with `Retry-After` (at most 10 s); `fastMode: true` and map are not held back. The bound holds across instances through a lease in Firestore (`hostedLeases`), freed after the call or 130 s after it was taken. A start now reads the key's record fresh rather than from the minute's cache, so revoking a key no longer leaves it working for up to a minute. The `hosted_usage` log line names the key by its HMAC's first 16 characters, never the key.
- A page of zero-width characters alone is no longer content (ROADMAP PA item 4, T031). Temu's verification page, reached on 2026-10-12 by a redirect from its home, showed no text: its Markdown was 300 zero-width spaces (U+200B). JavaScript's `trim()` and `\s` keep those characters, so the page was `success` with `onlyMainContent: false`, and the extractor counted 300 visible characters. The visible-text count and the whole page's emptiness check now leave out U+200B–U+200D, U+2060 and U+FEFF; the Markdown itself keeps them. Such a page is `failed`/`empty_unverified` with `textChars` 0, as a page of whitespace already was. A page near the router's text thresholds that writes joiners between its letters (Persian, some emoji) may route differently. The extractor is now `extract-tf/26`.
- A carousel is no longer taken for a page's listing (ROADMAP PA item 4, T006). On Amazon's home, read on 2026-10-12, the listing strategy took the hero carousel's six slides (`ul#gwm-window`), so the Markdown held 2,816 characters of slides while the page held a deck of category cards. A list is now passed over when it, an item of it, or an ancestor up to three levels holds `aria-roledescription` "carousel" or "slide", or one of those ancestors has as its own child a link or button labelled for a carousel or for a previous or next slide (Amazon's `Carousel previous slide`); a carousel elsewhere under a shared wrapper, or a pager's "Next page", does not count. Of 126 real pages extracted before and after (113 captured through the local API on 2026-10-12, proxied, and 13 Amazon home captures), only Amazon's homes changed: ten to their card deck (16,105 to 53,754 characters), two read before their cards had loaded to what had (one card's links, or the page around the empty deck), and one other layout from the article cascade to its card layout. The extractor is now `extract-tf/25`.
- A list in a page's footer is no longer taken for the page's listing (ROADMAP PA item 4, T006). The listing strategy took the list with the most linked items wherever it sat: on Amazon's home, read on 2026-10-12, it was the "Make Money with Us" links in `div#navFooter`, so the Markdown held the footer alone. `<footer>` and `<nav>` were already dropped before the choice; now a list inside `role="contentinfo"`, or inside an element named for a footer by its class or id (`footer`, `site-footer`, Amazon's `navFooter`, `footer-links`, `footer__inner`) that holds no `<h1>` or `<main>`, is passed over too. A name that says how the page lays out its footer (`has-fixed-footer`, `footer-fixed`, `pb-footer`) is a wrapper's and does not count; a footer named otherwise is read as before. When the footer held the only list, a container of linked blocks, else the article cascade, reads the page instead, as on a page with no list. Of 126 real pages extracted before and after, only Amazon's home changed, to its category cards. T006 still fails: that home showed no product prices, its five matches being three "under $25"-style card titles each written twice. The extractor is now `extract-tf/24`.
- `W2L_BROWSER_IDENTITY=actual`: the public browser rung sends the browser's own identity (a `HeadlessChrome` User-Agent and Chromium's own client hints) instead of the mode's declared Chrome identity, and the record declares the User-Agent it read from the browser. An experiment switch for ROADMAP PA's challenge-page work: on 2026-10-12 imf.org's edge refused a headless Chromium that claimed Google Chrome in every combination tried and served the same browser when it said what it is. Off by default; local servers only.
- The my-browser lane's `steady_wait` no longer counts the time it waited for a tab out of sight. That wait is said once, as `hiddenWaitMs` on `user_browser_read`. A StubHub read on 2026-10-12, its Chrome window covered, recorded a `steady_wait` of 30.4 s, which equalled the hidden wait, on a page that had not changed. `readiness.waitedMs` took the same 30.4 s.
- A page with DataDome's challenge laid over it is blocked, not content. Its iframe from `captcha-delivery.com` (`geo.` or another subdomain) is decisive wherever it sits on the page: `/interstitial/` (a device check) is `bot_detected_generic`, `/captcha/` is `captcha`. DataDome's tag alone (`js.datadome.co`), which pages it lets through carry too, decides nothing. StubHub's home, read from a Singapore exit on 2026-10-11, rendered with its events empty under that challenge, past 90 KB of markup; the local browser had answered it `success` with its navigation alone (T073).
- The wait for a task's region scrolls to a region that loads as it comes into view (ROADMAP PA items 4 and 11, ADR 0007's "not loaded: wait or act in the same session"). Home Depot's drills page (T014) shows its product grid, prices and all, only when it is scrolled into view. A Steel session through its US residential proxy on 2026-10-11 found 1 price after 25 s of waiting and 22 once scrolled. Now, on the local browser and a provider's browser, once a contract's check fails on a page that has settled, the wait scrolls one screen down before each read: until the checks hold, the page ends or 20 screens, within its 10 s. `region_wait` records `scrolls`. The my-browser lane does not scroll the person's own tab.
- A run that set aside only a robots.txt it could not read now goes on to a vendor rung. Before, any robots override on a local rung skipped every vendor rung, as if the publisher had written a rule. The provider reads robots.txt itself before it opens a session: if it reads a file that allows the URL, it fetches the page; if it still cannot read it, or a rule disallows the URL, it refuses. The earlier rung's answer then stands (`ladder_vendor_refused`). Such a refusal is charged as any call: the vendor's session is opened, to measure its User-Agent, before robots.txt is read for it, so the call costs its measured session time, else its price ceiling. A run that set aside a rule the publisher wrote still ends at its local rungs. In the 2026-10-11 ladder run, stackoverflow.com (T076) lost its Steel rung to one unreadable lookup.
- A Steel session's solves are read just before its release. Steel's `GET /v1/sessions/{id}/captchas/status` answers 404 some time after a release: on 2026-10-11 (arm B of the paid-configuration experiment) 4 of 17 reads after the release got none, and those calls were charged the ceiling's allowance of three solves. The transport now asks the adapter for the figures a provider only answers for while the session lives (`liveUsage`), before the release, and keeps them over the read after it.
- A Steel session's `proxyBytesUsed` is read again while it is still 0 under the residential proxy, and recorded as null when it stays 0. Steel fills the figure some time after the release: on 2026-10-11 (arm A of the paid-configuration experiment) 12 of 16 reads right after the release got 0, were recorded as 0 and charged nothing for bandwidth, where Steel's own session list showed 0.3 to 14.5 MB each. The adapter now reads again after 1.5, 1.5 and 2 s within the transport's six seconds; a figure still 0 then is null, priced at the ceiling's allowance.
- A data grid drawn with ARIA roles is read as a table (ROADMAP PA item 4, the remaining false successes). Eurostat's data browser draws its tables with AG Grid as `div`s (`role="treegrid"`, rows and cells), its pinned first column in a container of its own. Its population figures were read as text and no table, so the task asking for one (T055) failed though the data was there; no other route measured read it either. The extractor now rewrites such a grid (`grid`, `treegrid` or `table`, two rows or more) as a `<table>` before the Markdown and the `tables` format are written, putting a row split across containers back together by `aria-rowindex` and `aria-colindex`. The region wait's table count on the live page counts a `treegrid` too, and only the outermost grid, as the extractor reads it. The extractor is now `extract-tf/23`.
- Sign-in for octocrawl.dev, on the server side: GitHub, Google or an email link through Firebase Authentication's REST API, with no Firebase script in the page and the CSP unchanged. Opening an email link shows a button rather than signing in, so a mail scanner cannot use the link up. A sign-in opens a 30-day session (`w2l_session`, kept in Firestore under its HMAC), records the account in `users/{uid}`, and `/api/me` says who is signed in. The uid is the one the hosted API's credits are kept under. It is served only when `W2L_FIREBASE_API_KEY` is set. `/signin/` offers the three ways in. `/account/` shows the credits left this month, the last 30 days of use, and the account's keys. A key is made there, shown once and revoked there, at most five at a time, and its calls spend the account's credits. The header's Sign in link reads Account once signed in. The privacy page, terms and Limits say what an account keeps and costs. See docs/public-preview.md, Sign-in.
- octocrawl.dev's account page is now a dashboard at `/dashboard/`, on the site's navy with orange and text charts: Overview (this month's credits, 30 days of pages read and not charged, an ASCII chart of credits per day, the lines to connect an agent), Usage (day by day), API keys, Connect and Account (the ways the account signs in, from `GET /api/account`'s new `providers`). Sign-in lands there, and `/account/` answers with a 301 to it.
