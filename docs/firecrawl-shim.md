# Firecrawl scrape/crawl shim

Snapshot date: **2026-09-18**. Source: Firecrawl API v1
[`POST /scrape`](https://docs.firecrawl.dev/api-reference/v1-endpoint/scrape),
[`POST /crawl`](https://docs.firecrawl.dev/api-reference/v1-endpoint/crawl-post),
[`GET /crawl/{id}`](https://docs.firecrawl.dev/api-reference/v1-endpoint/crawl-get).

This is a **one-shot migration tool**, not a compatibility layer. Point a
Firecrawl v1 client at `http://127.0.0.1:8787/fc` so its `/v1/scrape` and
`/v1/crawl` calls hit the shim, which translates them onto the native
contract (`POST /v1/scrape`, `POST /v1/crawl` 202, `GET /v1/crawl/:id`).

Covered:

- `POST /fc/v1/scrape` → native scrape → `{ success, data }`
- `POST /fc/v1/crawl` → native crawl start → `{ success, id, url }` (HTTP 200)
- `GET /fc/v1/crawl/:id` → the crawl's status, counts and one page of its steps → Firecrawl crawl status, further pages through `next`

Not covered: Search, Interact, Agent, Monitor and Extract will not be added. Map is not implemented yet; the [roadmap](../ROADMAP.md) schedules a native `map` endpoint for P2.

## Known diffs

- Challenge / block pages are `success: false`. Firecrawl often returns the interstitial as success markdown.
- A page answered with an HTTP error status (4xx/5xx) is `success: false`, with its Markdown in `data.markdown` and the status in `data.metadata.statusCode`: the error page is evidence of what the server said, not content.
- A page on which W2L finds no main content is `success: false` with `failed: empty_unverified` and the whole page's Markdown in `data.markdown` as evidence; with `onlyMainContent: false` it is `success: true` with that Markdown. Firecrawl returns whatever its converter kept as success.
- A page whose server HTML is a shell for data its scripts fill in (a `<table>` with no cells beside scripts, an empty application root, an element hidden once scripts run) is fetched again on the browser rung, as a thin page is, and the rendered page is the answer when it holds more; otherwise the HTTP page is returned, and the native response then carries `client_rendered_suspected` and `low_content_yield` warnings (`The http lane extracted N tokens at confidence C; the browser lane did not improve it.`, or `… was not available to this request.` when no browser rung was permitted), whose messages `/fc` passes through as `data.warning`, one string joined with a space, as it does for every native warning (a recorded robots override, an unverified certificate). Firecrawl renders every page in a browser, and its `warning` has no fixed wording.
- `data.metadata` has `title` (the page's `<title>`), `description`, `language`, `keywords`, `robots` and `favicon` only when the page declares them, next to `sourceURL` (the requested URL), `url` (the final URL, after redirects, a script or a meta refresh included), `statusCode` (the status of the response that answered `url`, `null` when none did), `contentType` (that response's `content-type` header, left out when there was none) and `error` on a page that is `success: false`: W2L's failure, block or budget reason code, such as `http_error` or `cloudflare_challenge`, or its status when it has none, such as `empty_verified` (the top-level `error` puts the status first, as in `failed: http_error`). `keywords` is the declared string, not split. The Open Graph tags (`ogTitle`, `ogDescription`, `ogUrl`, `ogImage`, `ogAudio`, `ogVideo`, `ogDeterminer`, `ogLocale`, `ogLocaleAlternate` as a list, `ogSiteName`), the Dublin Core tags (`dcTermsCreated`, `dcDateCreated`, `dcDate`, `dcTermsType`, `dcType`, `dcTermsAudience`, `dcTermsSubject`, `dcSubject`, `dcDescription`, `dcTermsKeywords`) and the article tags (`publishedTime`, `modifiedTime`, `articleSection`, `articleTag` joined with `, `) are passed through under Firecrawl's names, each only when the page states it, as written: no date normalisation and no fallback from another tag, JSON-LD or the content. `twitter:*` and other `<meta>` tags are not passed through, and a failed or blocked page, an error-status page included, has none of these.
- No fire-engine, proxy pools, `actions` or JSON extract.
- Resume / cache defaults to refetch. A Firecrawl body never sets `useCached`.
- Omitted `limit` / `maxDepth` stay unbounded on a local server. A hosted server enforces its crawl limit (100 pages): an omitted or `null` `limit` takes it, and a larger one is refused with HTTP 400 `invalid_request`. Firecrawl defaults are 10000 / 10.
- `maxDepth` counts link hops from the start URL, which Firecrawl calls `maxDiscoveryDepth`; Firecrawl's own `maxDepth` limits URL path depth.
- Shim crawl start is HTTP 200 `{success,id,url}`. Native crawl start stays 202 `{taskId}`.
- `creditsUsed` and `expiresAt` are `null`: W2L counts no credits and keeps crawl results until their task directory is deleted.
- Crawl status `status` is `scraping` while the crawl is pending, running or paused (a paused crawl resumes when the API starts again), then `completed`, `failed` or `cancelled`.
- Crawl status describes the crawl's latest attempt; a resumed crawl starts a new one. `completed` counts its pages that succeeded (native status `success` or `partial`). `data` lists all its pages in the order they were recorded; a failed, blocked or duplicate one (its content repeats an earlier page's) has `metadata.error`. A failed or blocked page's `markdown` is the page W2L received, kept as evidence and never content (a 404 or block page), or `null` when there was none; a duplicate's is `null`. So the pages of `data` can hold more entries than `completed`. Firecrawl lists successful pages only. `total` is all the attempt's pages plus, while this API process runs the crawl, the pages in flight and those queued within `limit`; it grows as the crawl finds links. Once the crawl is finished, `total` is what the attempt tried. While an unfinished crawl runs in no process here (paused, or left by a crash before the API restarted), and for a moment after a start or resume before the run has opened its queue, `total` is `null`: W2L does not store its queue.
- Crawl status `data` holds up to 100 pages (`?limit=` 1 to 1 000). `next` is the URL of the following page, carrying W2L's own `cursor`, built from the URL the request reached the API with. It is there while more pages are stored or the crawl is not finished, and left out after the last page of a finished crawl, as Firecrawl leaves it out. Firecrawl's `skip` and any other query parameter are rejected with HTTP 400 naming it; follow `next` instead.
- Scrape maps `url`, `formats`, `onlyMainContent`, `includeTags`, `excludeTags`, `waitFor`, `timeout`, `headers`, `mobile`, `skipTlsVerification`, `fastMode`, `blockAds` and `removeBase64Images`; crawl maps `url`, `limit` (as `maxPages`), `maxDepth`, `includePaths`, `excludePaths` and the same `scrapeOptions` (applied to every page). The formats are `markdown`, `links`, `html`, `rawHtml`, `images`, `screenshot` (the string, v1's `screenshot@fullPage`, or one `{ "type": "screenshot", "fullPage", "quality", "viewport" }` entry, checked by the native rules) and one `{ "type": "attributes", "selectors": [{ "selector", "attribute" }] }` entry (Firecrawl's v2 shape, checked by the native rules: 1 to 50 selectors, a selector W2L does not match is HTTP 400 by name). `ignoreSitemap: true` is accepted because W2L already works that way, and `origin` (the SDK's client label) and `integration` (yours) are stored on W2L's own records, the scrape record (`GET /v1/scrapes/:id`) and the crawl task, and never sent to the target or echoed. Any other parameter, format or value, such as `json`, `actions`, `location` or `proxy`, is rejected with HTTP 400 `{ success: false, error, code, details }` naming it (`code` is `unsupported_parameter` or `unsupported_format`).
- `data.screenshot` is the rendered page as an image, a `data:image/png;base64,…` string (or `image/jpeg` with `quality` 1 to 100), as Firecrawl v1 clients read it. A request with the format runs on the local browser rung alone (no HTTP attempt; a server without a browser rung refuses it with HTTP 400 `screenshot requires the browser lane, which this deployment does not offer`, and `fastMode` beside it is refused too). The capture is taken after load, stability and `waitFor`, before the DOM is read, CSS-pixel sized at the declared 1280x800 viewport (device scale factor 2 is declared, not baked into the image) or at the `viewport` asked for (integers 320..1920 by 240..1080, within the declared screen; a window size, not a change of identity); `fullPage` captures the document's whole height at that width without scrolling first, so sections a page loads on scroll may show unloaded. A capture the browser could not make is `null` with a `screenshot_unavailable` warning (passed through in `data.warning`) while the page stands; a file and a page that was not rendered have `null` too. The native response carries the capture as `screenshot: { contentType, width, height, fullPage, viewport, deviceScaleFactor, quality, bytes, sha256, path, base64 }`. Firecrawl captures at its own viewport and may return a URL instead of the image.
- `data.images` is every image URL of the whole document as received (`img` `src` and `srcset` candidates, `<picture>` sources, the lazy attributes `data-src`, `data-srcset`, `data-lazy-src` and `data-original`, `video[poster]`, `<link rel="image_src">`, `og:image` and `twitter:image`), resolved against the document base, absolute http(s), fragment stripped, each once, in document order, `data:` URIs left out; `includeTags`, `excludeTags` and `onlyMainContent` do not narrow it, and there is no file-extension filter. `data.attributes` gives, per selector in request order, the named attribute's values as written in the HTML (not resolved), elements without the attribute skipped, `[]` when nothing matches. Both appear only when asked for and only on a page read as content: a file and a page that is `success: false` carry neither. `removeBase64Images` (default `true`) leaves an `<img>` with a `data:` `src` out of the Markdown and keeps its alt text, where Firecrawl writes a `(<Base64-Image-Removed>)` placeholder; `false` keeps the image as `![alt](data:…)`. `html` and `rawHtml` are never rewritten.
- `headers` never override the declared identity: a `User-Agent`, any `sec-ch-*` or `sec-fetch-*` header, a credential (`Authorization`, `Proxy-Authorization`, `Cookie`) or a transport header (`Host`, `Accept-Encoding`, ...) is HTTP 400 naming it, where Firecrawl sends what it is given. The headers go to the requested origin (the page, its same-origin hops and, on the browser rung, the files it loads from that origin) after the identity; robots.txt gets the identity alone, and so does a redirect hop to another origin on either rung (the native trace records it as `custom_headers_withheld`). Everything in `headers` is on the record (the trace, the browser rung's signed `sentHeaders`), so a secret does not belong there.
- `mobile: true` fetches as a declared Android Chrome identity (User-Agent, client hints, a 412x915 touch viewport) that robots.txt is evaluated against and the record carries; the page is whatever the site serves to it (its mobile host, a responsive layout, or a page without a viewport meta laid out at 980 CSS pixels as on a phone), with no DOM rewriting. It is W2L's second declared identity, not a disguise, and is refused with mode `research`, which the shim does not take anyway.
- `skipTlsVerification: true` relaxes certificate verification for one local request and its robots.txt lookup; the native response records it (`tls_verification_skipped` in the trace, a `tls_unverified` warning), which `/fc` does not pass through. A hosted W2L refuses it with HTTP 400. Without it a certificate that does not verify is `success: false` with `failed: tls_error`. Firecrawl's Python SDK sends `true` by default; W2L verifies by default.
- `fastMode: true` keeps the HTTP rung alone: a page whose content its scripts write is `success: false` with `failed: empty_unverified`, never rendered, and the native response says so in `agentHints`, which `/fc` does not pass through; `waitFor` has no effect under it. Firecrawl's fast mode still renders.
- `blockAds` (default `true`) aborts requests to a bundled list of about fifty ad-serving hosts on the local browser rung and removes ad and cookie-banner elements before extraction; `false` keeps them in `markdown` and `html`. The list is curated, not EasyList, so ads from hosts outside it load; a hosted W2L's browser keeps its host allowlist whatever `blockAds` says.
- `data.html` is the cleaned HTML `data.markdown` is written from: the main content; with `onlyMainContent: false` the page's `<body>` with its header, navigation and footer, without scripts, styles, form controls and embedded media; with `includeTags` a `<body>` holding the named elements. Firecrawl's `html` comes from its own cleaning and can differ. `data.rawHtml` is the page as the answering rung received it: the response body on the HTTP rung, the rendered DOM on a browser rung. Both are present only when `formats` asks for them, and are `null` for a file and for a page that is `success: false`, which keeps its Markdown as evidence only. A scrape whose `formats` leave out `markdown` has `data.markdown: null`.
- `includeTags` keeps only the elements its CSS selectors name, in document order, taken from the page before any cleaning, whatever `onlyMainContent` says; Firecrawl's handling of the two together can differ. When nothing is named the page is `success: true` with empty Markdown, unless a later rung finds it blocked, which is then the answer (`success: false`). `excludeTags` removes elements from the main content, the whole page and an `includeTags` selection; both lists are matched against the page as it was received. W2L takes tag, class, id and attribute selectors, the descendant and child combinators, `:root`, `:empty`, and `:not()`, `:is()` and `:where()` around selectors without combinators, at most 100 selector parts per list (a longer list is HTTP 400 `invalid_request` naming the count). A selector that does not parse is HTTP 400 `invalid_request`; one that uses a sibling combinator (`+`, `~`), a positional pseudo-class such as `:nth-child` or `:first-child`, `:has()` or any other pseudo-class is `unsupported_parameter`, naming what it uses (see the [README](../README.md) for why). Firecrawl's selector support is its own engine's and can differ. The errors name the native field (`includeTags[0]`), also for a crawl's `scrapeOptions`.
- `data.metadata` also carries the facts of the call under Firecrawl's names: `scrapeId` (a UUID per call; `GET /v1/scrapes/:id` on the native API returns the call's record, which holds the request, `origin`, `integration`, the verdict, the lanes tried, the metadata, the snapshot, the usage, the warnings and the hints, and no page body), `proxyUsed` (`operator` for the server's environment proxy, `user` for the caller's own egress on the browser rung's compliance record, else `null`), `timezone` (the browser rung's declared zone, `null` on the HTTP rung, where none goes on the wire), `creditsUsed: null` (W2L counts no credits), `concurrencyLimited` and `concurrencyQueueDurationMs` (whether the per-origin ceiling, `W2L_PER_HOST_CONCURRENCY`, held the fetch back and for how long; Firecrawl's pair reports a per-account limit). `cacheState` and `cachedAt` are left out until W2L has a cache; a crawl status page has no call of its own and leaves all of these out.
- A page W2L has advice about carries `data.agent_hints`, one sentence each, never page text (the native response calls them `agentHints`): a login wall points to `mode: authed` with your own session, a robots.txt denial names the rule and the recorded override, a challenge or bot gate names the lanes tried and says W2L neither solves challenges nor changes its identity, a Retry-After gives the time to wait, a cut names the character, a script-filled shell says whether the browser rung had its turn, a thin HTTP answer the browser rung did not improve on (or could not be offered to) suggests `waitFor` or a longer `timeout` with the browser rung available, an error page says its Markdown is not the page asked for, and a file says what its `markdown` is (a PDF's text layer, a CSV's text as received, none for XLSX, XLS and ZIP). The hints come from a fixed table, never from page text. A request refused for `stealth`, `proxy: stealth` or `enhanced`, or `ignoreRobotsTxt` carries `agent_hints` in its error envelope naming the supported route, and a caller over the server's per-minute rate limit (`W2L_RATE_LIMIT_PER_MINUTE`) gets HTTP 429 `{ success: false, error, code: "rate_limited", agent_hints }` with a `Retry-After` header; Firecrawl's SDKs do not retry a 429 and neither does W2L's.
- `robotsOverride` (a recorded decision to fetch one URL although its host's robots.txt disallows it) is W2L's own option and is not accepted on `/fc`, in a crawl's `scrapeOptions` either; use the native API of a local server for it (a hosted server refuses it). `ignoreRobotsTxt` is rejected by name on `/fc` as on the native API: W2L always reads robots.txt and offers no blanket switch.
- Every shim error carries the native API's error `code` inside Firecrawl's `{ success: false, error }` envelope; see the [error-code table](../apps/public-web/content/reference.md#errors). A page that fails is not an error response: it stays HTTP 200 with `success: false` and no `code`.
- `onlyMainContent: false` returns W2L's Markdown of the whole page body (scripts, styles, form controls and embedded media left out; header, navigation and footer kept). Firecrawl's full-page output comes from its own converter and can differ.
- `waitFor` (0 to 60 000 ms) skips the HTTP rung, which cannot run scripts, and starts at the local browser rung; with no browser rung the page is `success: false` with `failed: policy_denied`. The wait counts toward `timeout`.
- `timeout` must be 1 000 to 300 000 ms; an omitted one stays W2L's 300 000 ms (Firecrawl: 30 000). When it fires, the answer is still HTTP 200: `success: true` with the content fetched so far (native status `partial`), or `success: false` with `failed: timeout`. Firecrawl answers a timeout with an error. As on the native API, the lanes wait for a slow server until a `timeout` you set, instead of their default 10 s for headers and 20 s for navigation.
- Scrape without `formats` returns markdown and links; Firecrawl returns markdown only. Crawl status pages carry each page's links whatever `scrapeOptions.formats` says.
- A PDF answers `success: true` with its text layer as `data.markdown`, a line `<!-- page N -->` before each page (N counts pages in the file), which Firecrawl's PDF Markdown does not have; `data.metadata` has no `numPages` (the native response's `file.pdf.pageCount` has it) and none of the PDF's own title or language. A PDF with no text layer at all is `success: false` with `failed: empty_unverified`: W2L runs no OCR. CSV, JSON and plain-text files give their text as received; XLSX, XLS and ZIP files are `success: true` with `data.markdown: null`, the file itself saved on the W2L host. A file over `W2L_MAX_FILE_BYTES` (default 50 MiB) is `success: false` with `failed: body_too_large`; images, video and similar are `failed: unsupported_content_type`. `maxFileBytes` is W2L's own option and is not accepted on `/fc`.
- `includePaths` / `excludePaths` are regular expressions matched against the URL path of each discovered link, as in Firecrawl. The start URL is always fetched and an `excludePaths` match wins. W2L refuses with HTTP 400 `invalid_request` a pattern that can backtrack catastrophically, such as `^/(a+)+$` or `.*a.*b`. It matches the rest in linear time where V8's linear-time engine can run them, and runs one with a lookaround, a backreference or a counted repetition above 16 only on paths of up to 2,048 characters with a 100 ms limit per link; a link a filter cannot decide is not followed. W2L follows links anywhere on the start URL's host, its `www.` twin and the host the start URL redirects to; Firecrawl's default follows only paths below the start URL, and `crawlEntireDomain` is rejected.
