## 1. 先回答你的问题

**美国是不是最卷？** 是，但"卷"在不同的层：
- **在 T4（写 agent 和 RAG 的构建者，付费层）上最卷。** Firecrawl 2026-09-22 完成 7,500 万美元 B 轮，自称 150 万用户（官网写 125 万开发者），GitHub 约 20 万星，PyPI 30 天 594 万次；Exa 2.5 亿美元 C 轮、估值 22 亿美元；Tavily 已宣布被 Nebius 收购（是否完成未查）；入门付费档几乎都挤在每月 19 美元（调研 §4）。
- **在 T3（用编码 agent 的开发者，入口层）上没有被关死。** Context7 从 2025-04-18 的 141 颗星到 05-09 的 6,854 颗，用了三周；Crawl4AI 在 2024-09-28 到 10-01 的三天里从 4,329 涨到 8,353。起飞时间上对得上的是创作者视频、趋势榜和编辑器论坛，不是资金（调研 §7.1，相关性，没有来源说明原因）。
- **美国也是信号最强的地方。** JetBrains 称美国专业开发者工作中 Claude Code 使用率 47%（全球 39%），Claude.ai 消费端人均使用靠前（AUI 3.62，2025-08 一周的样本，不含 API、Claude Code 与 MCP；韩国 3.73、以色列 7 更高）。

**其他国家怎么样？**

| 地区 | 一句话 | 证据强度 |
|---|---|---|
| 韩国 | 非美国里需求信号最强、最集中，且有直接的分发渠道（Kakao PlayMCP）。开发者基数小（软件开发者约 25.9 万）。 | 需求【中】，渠道有效性【弱】 |
| 日本 | 开发者基数更大（GitHub 账号 624 万、同比 +46%）、内容社区成熟（Zenn 的 MCP 话题 4,002 篇文章）、自付 AI 订阅比例高（14%）。对手已有日文文档。 | 【中】，渠道案例【未知】 |
| 欧洲 | 价值在**定位**而不在用户量：把 robots.txt 决定和抓取时间写进每条记录，方向与 GPAI 行为准则、EDPB 和 CNIL 的措辞一致。法律最重，且适用于"按需抓取"没有定论。 | 法律文本【强】，适用性【弱】 |
| 中国大陆 | 基数最大、MCP 与 RAG 栈成熟，但托管服务的可达性未测、收款只能一次性、Claude 用不了、法律对规避措施严厉。 | 障碍【强】，机会规模【弱】 |

**建议。** 美国继续做第一入口；日本和韩国各做一次**两周、零工程的低成本实验**，用结果定先后；欧洲只做定位与访谈，不专门投放；中国先做**本地优先**，托管推广等可达性测完再说。理由和限制见 §4。

## 2. 三条原则

**1. 一扇门，两个信息。**
- 门：T3，在编码 agent 里读 Context7 和 `llms.txt` 覆盖不到的页面。
- 第一个信息（既定措辞，Howard 此前的决定）：Markdown，省 token。
- 第二个信息：Evidence Record，页面读不到时如实说，不当成功交付。
- **不要把"失败不计费"当第一卖点。** Crawl4AI Cloud 官方写明被拦、登录墙、无应答都不收费，ZenRows、Jina、Tavily、Spider 也有类似说法（多数是研究员读取、未复核）；Firecrawl 对返回了文档的 403 和 404 页仍收费，但**没有说** HTTP 200 的拦截页怎么算（调研 §4.5）。差别在于**记录里有什么**，不在计不计费。
- **不要说"能读任何站"。** ROADMAP 记录：50 个冻结任务上，Octocrawl 最强路线验证了 25 和 31 个（两个窗口），Firecrawl Cloud 是 33 和 34 个。

**2. 找"人"，不是找"平台"。** 证据里的起飞靠的是具体的人：
- Context7：Better Stack 与 Cole Medin 的 YouTube 视频、Cursor 论坛的用户推荐（另有 04-20 的一个 Smithery 配置，未经核查员复核，且与 04-21 的视频混在一起，分不出各自的作用）；Hacker News 那条只有 3 分。npm 日下载在 2025-04-16 和 04-21 两次跳升，**下载先于星数**（调研 §7.1，相关性，不是因果）。
- Crawl4AI：趋势榜第一，维护者点名感谢 @tom_doerr 的一条帖子。
- 韩国 AutoRAG：LlamaIndex 官方帖子让它从约 300 涨到 500 多颗星，YouTuber Teddynote 的直播两天内约 +110（690 涨到 800 多，几天后 900）；它在 GeekNews 的投稿只有 11 分是研究员的说法，核查员读不到那个页面。
- 中国 vfox：一个月的多平台转发"几乎没有效果"，真正的流量始于 HelloGitHub 维护者主动推荐。
- 一份 138 个 AI 仓库的研究：登上 Hacker News 后平均一周 +289 星，Show HN 标签没有优势（均值，不是中位数）。Firecrawl 自己的 Show HN 只有 23 分。

**3. 零工程。** 本阶段每个动作都能不改引擎完成。需要工程的（如 Dify 插件）单独列出，等 Howard 决定。

## 3. 全球都做的五件事

1. **给每个渠道一个来源标记。** 站点已经把首次来源写入 `w2l_src`（`utm_source`）并记在 `users/{uid}.firstSource`。每个渠道用固定名字：`utm_source=geeknews`、`velog`、`zenn`、`qiita`、`v2ex`、`linuxdo`、`hellogithub`、`youtube`、`cursor-forum` 等，写在你发布的链接里。**限制（据站点代码 `packages/public-preview/src/site.ts` 的读取）：** `w2l_src` 只在人先打开官网时写入；通过 Kakao PlayMCP 或 Le Chat 直接添加 MCP 地址的人不会经过带标记的官网链接，他们的登录会被记成 `via:mcp-oauth`、`direct` 或引荐域名。所以目录和连接器渠道要靠 MCP 客户端名称、注册时间和访谈时问一句"你是怎么找到的"来判断。没有来源标记，两周后无法回答"哪个渠道有效"。
2. **目录注册。** 官方 MCP Registry、Smithery、Glama 已经有；PulseMCP 在 2026-10-26 的品牌核对里查不到（平台当时暂停新提交），MCP.so 未匹配（出自 2026-10-26 的品牌身份核对，只做了只读检索；该文件在主工作区的 `docs/seo/2026-10-18-nonbrand/` 下，本分支没有提交，读不到时以重新检索为准）（最近 30 天 288 个客户端名称里，排在前面的大多是目录和探测机器人，说明被收录，不说明有用户，调研 §1.2）。新增：Kakao PlayMCP（韩国）、Mistral 的 connector（欧洲）、魔搭 MCP 广场（中国，等可达性）。
3. **本地语言的一页说明。** 每页只回答三件事：一行命令、一个例子、读不到时怎么看记录。日文、韩文、简体中文各一页，放在官网文档里；不翻译整站。
4. **访谈。** 用画像文档末尾的 8 个问题，每周至少 3 个人，先 T3 与 T4。
5. **每个试用（有人用自己的任务跑完）都落到 `research/trials/`。** ROADMAP 当前阶段的退出条件是十个外部用户各完成一个自己的任务、各有一份试用记录；访谈本身不算试用，记在仓库外的外联日志里。

## 4. 分地区打法

### 4.1 美国与加拿大：第一入口

**目标层：** T3（入口），T4（有痛点的人）。

**为什么。** 需求信号最强、英文渠道已经成型、Stripe 与现成的 MoR 可选（调研 §8.1；但 MoR 会不会批准抓取产品没有问过）。第一批用户最可能从这里来，但这是推断，Octocrawl 自己没有转化数据（调研 §1.2：30 天内没有任何一条 Cursor、Codex、OpenCode 连接）。

**动作（每周 10 条消息里的主要份额，建议 5 条）。**
1. **创作者与策展人**：列出 10 个做过 Context7、Playwright MCP、Claude Code 教程的频道和账号，带一个具体例子联系他们，例子要真：用 Octocrawl 让 Claude Code 读一个 Context7 没有的文档站。
2. **编辑器与助手社区**：Cursor 论坛、r/ClaudeAI、r/mcp，由 Howard 用自己的话发，不用模板。Cursor 论坛 2025-04-16 就有用户推荐，与第一次下载跳升同一天；这是个例。
3. **Show HN**：只有一次机会，沿用既有计划里的日期，不提前。数据：均值一周 +289 星，Firecrawl 自己的 Show HN 是 23 分，Context7 的是 4 分。**不要把 HN 当主渠道。**
4. **T4 的"从 Firecrawl 迁移"**：写成对照文档，只写核查过的事实（见 §5）。先自己测一次"HTTP 200 的验证码页是否被扣积分"（免费账号有 1,000 积分，足够测一次；需要更多积分时再买 Hobby 档，约 19 美元，见 §9），测完再写。

**注意。**
- 【强】*Amazon v. Perplexity* 的判决只认定：在那份记录下，Perplexity 的服务器不联系 Amazon 的服务器，所以 Amazon 不太可能证明 Perplexity"访问"了它；法院明确保留了其他情形。【推】Octocrawl 托管服务由自己的服务器直接抓取，是该案件的"相反架构"，用户自己的 Chrome（本地模式）才接近 Comet；这个对应是我们的推断，律所只说"避免直接连接"（调研 §6.1）。推广托管版之前，找律师问清这一点。
- 不要在推广里提增强访问、绕过拦截或验证码；Polar 与 Paddle 的禁止清单离这些词很近（调研 §8.1）。
- 加拿大：PIPEDA 对"公开个人信息"的处理比美国严；不要推广个人信息抓取（ROADMAP 本来就把销售线索抓取个人数据排除在范围外）。

**两周内的检验。** 来自创作者与社区的外部注册数（按 `firstSource`）；至少 3 次访谈；至少 1 份 `research/trials/` 记录。

### 4.2 韩国：第二，做一次低成本实验

**目标层：** T3。

**为什么。** 非美国里信号最集中（调研 §9.2）：Anthropic 在 2025-10 称韩国 Claude Code 周活四个月增长 6 倍，2026-06 称 NAVER 全工程组织部署；OpenAI Korea 在 2026-09 称 ChatGPT Work 与 Codex 周活半年约 14 倍（二者**都没有基数**）；Kakao PlayMCP 约 200 个外部服务器，据线索**以远程 MCP URL 注册**（未读条款），与 Octocrawl 的托管 MCP 形态一致；Stripe 支持 Kakao Pay、Naver Pay（含定期扣款），无需韩国实体；Firecrawl 文档没有韩文版（`/ko` 返回 404，2026-11-09）。

**动作。**
1. 韩文一页说明（见 §3）。
2. 注册 Kakao PlayMCP（先读它的条款和审核要求，调研没有读到）。
3. 一篇 Velog 文章加一次 GeekNews 投稿。**预期要低**：GeekNews 上介绍 Firecrawl 的帖子是 15 分 2 评论；AutoRAG 的 GeekNews 投稿 11 分（研究员的说法，未核实）。
4. 联系 Claude Code Meetup Seoul 的组织者和 3 位韩国开发者做访谈（Anthropic 说 Claude Meetup 自 2025-09 起吸引"数百名"韩国开发者）。
5. **验证一个具体假设**：Context7 从 GitHub 收录时会跳过正文主要不是英文的页面。选 20 个韩文文档站（例如 Kakao Developers、Naver Cloud 的文档，仅为示例），看它们在 Context7 里有没有，有没有 `llms.txt`，Octocrawl 读出来怎么样。如果成立，这就是**非英语文档的楔子**；如果不成立，就放弃这个说法。网站来源路线是否也跳过非英文页面，调研没有读到，要实测。

**注意。**
- 【中】Naver 的 `search.naver.com`、`shopping.naver.com` 的 robots.txt 对所有爬虫 `Disallow: /`，并写明禁止 AI 训练与 RAG；托管版会如实报告被 robots.txt 拒绝。Coupang 对核查员的请求连 robots.txt 都返回 Akamai 的 403。**不要承诺能读韩国大站。**
- 税：外国供应商向韩国客户提供数字服务需要在 20 天内做简易增值税登记，没有门槛（来源是会计师事务所说明，未读法条）。在拿到 MoR 书面答复前，只提供免费额度。
- 韩国 AI 基本法要求外国经营者在达到门槛时指定国内代理人（上一年收入、AI 服务收入，或最近三个月日均 100 万韩国用户，金额待对照施行令，调研 §6.2）；"日均 100 万用户"这一条远高于 Octocrawl 现状，其余没有核对，所以暂时不构成问题（这是我们的推断）。

**两周内的检验。** PlayMCP 注册是否通过；`firstSource` 为 `velog`、`geeknews` 的外部注册数（PlayMCP 的流量看 MCP 客户端名称与访谈，见 §3）；3 次访谈；文档站实测的结果。

### 4.3 日本：并列第二，同样的实验

**目标层：** T3，T4。

**为什么。** 需求面的基数比韩国大（GitHub 账号 624 万对 350 万，同比 +46%）；Findy（n=943，自选样本）六成以上的受访工程师用 Claude Code；JUAS 调查的东证上市等大企业里，32.6% 已采用或处于试用与准备中的代码类生成式 AI（n=952）；自付 AI 订阅 14%；内容量大（Zenn 的 MCP 话题 4,002 篇文章；Qiita 的 mcp 标签 3,734 篇是未复核的线索；Classmethod 的 MCP 活动最终 480 人报名）；著作权法第 30 条之 4 对信息分析友好（调研 §9.3）。限制：Microsoft 遥测只有 24.7%；Firecrawl 有日文文档；**没有找到 Zenn 或 Qiita 带数字的增长案例**。

**动作。**
1. 日文一页说明。
2. 一篇 Zenn 文章：用 Claude Code 或 Cursor 通过 Octocrawl 读一个日文文档站。
3. 联系一个 connpass 上的 MCP 活动申请 LT（短演讲）。Classmethod AI Talks 是已知的例子。
4. 3 次访谈，优先 Findy、Qiita 的用户群。
5. **同一个假设的实测**：20 个日文文档站在 Context7、`llms.txt`、Octocrawl 里的情况。

**注意。**
- 【强】日本国税厅：外国企业向日本提供面向消费者的电子服务，自己要申报缴纳消费税（10%）；自助注册、无法实际排除消费者的产品，即使声称只面向企业也算面向消费者。**所以在拿到税务意见前，日本只提供免费额度。**
- 日本本土没有找到公开日元月价的自助式抓取 SaaS；这是可能的空位，也可能只是没找到（调研 §8.4）。**先问访谈对象怎么买，不要先定日元价格。**
- ウェブ魚拓（网页证据）是现成的付费产品（批量一次性 1,000 页内 6 万日元），说明 T5 在日本有真实预算，但那是"保存网页"，不是"数据抽取"（调研 §5.2）。

**两周内的检验。** 与韩国相同，另加 Zenn 文章的阅读量和 `firstSource=zenn` 的注册。

### 4.4 欧洲：定位与访谈，不专门投放

**目标层：** T5（定位验证），T4。

**为什么。** 法律文本在这里最重，但方向与 Octocrawl 一致（调研 §6）：GPAI 行为准则要求签署方遵守 robots.txt；EDPB 草案、CNIL 把 robots.txt 当成反对抓取的信号；AI Act 训练内容摘要模板要写爬虫名称、收集时段、域名清单。Octocrawl 的 Evidence Record 记录最终 URL、时间、状态、robots.txt 决定和哈希，**与这些要求同向，但不等于合规**。Jina（柏林）已被 Elastic 收购，Tavily 已宣布被 Nebius 收购（是否完成未查）。

**动作。**
1. 一页"Evidence Record 与欧盟规则"的说明：只写**记录了什么**，不写"合规"。要有免责说明。所有适用于"按需抓取"的说法都标注"未经律师确认"。
2. 在 Mistral Le Chat 里把托管 MCP 注册为 connector（文档称任何兼容 MCP 的服务都可以，研究员读取，未复核），测一次能不能用。
3. 3 次访谈：做 RAG 或内部知识库的德国、法国、荷兰团队。问数据驻留是否是问题（Bitkom：98% 的德国企业说云服务商的原产国会影响选择；但没有找到禁止美国托管服务的采购规则）。
4. 关注两个日期：BGH 对 LAION v Kneschke 的宣判（2026-12-17）、欧盟法院 C-250/25 的判决（总法务官意见已在 2026-11-03 发表，判决待定）。

**注意。** 英国没有商业性的 TDM 例外；欧盟 TDM 退出没有统一标准，**只看 robots.txt 不能说明合规**（欧洲议会研究的说法，是解读，不是判决）。VAT 用 MoR 代办最省事（Polar 自己是 EU OSS 登记主体）。

**两周内的检验。** Le Chat 注册结果；3 次访谈；"数据驻留"这个问题被提到几次。

### 4.5 中国大陆：本地优先，托管等测试

**目标层：** T3、T4（使用 Cursor、Trae、通义灵码、Qwen Code、Kimi 的开发者）。Claude 用不了（Anthropic 的支持国家不含中国），所以不能指望 Claude Code 路线。

**为什么现在不推托管。** 四件事都没有解决（调研 §9.5）：
1. **可达性未测。** GreatFire 对 `octocrawl.dev` 没有任何测试数据；`workers.dev` 231 个测试 URL 里 215 个被封，`run.app` 22 个里 18 个时断时续（`r.jina.ai` 被封是未复核的线索）。
2. **收款。** Stripe 的支付宝与微信支付只能一次性（微信仅 B2C），Stripe Managed Payments 不能向中国客户销售。预付积分可行，月度订阅不行。
3. **法律。** 《反不正当竞争法》第十三条第三款和"丁某案"对规避技术措施严厉；规避登录限制的程序在刑法第 285 条下有实例。
4. **备案。** 没有找到要求境外托管服务备案的条文，但也没有找到明确豁免（调研 §6.2）。

**现在能做的。**
1. **先测可达性（需要 Howard）。** 用一台大陆的 VPS 或国内拨测服务，测 `octocrawl.dev`、`mcp.octocrawl.dev`、`api.octocrawl.dev`。这是中国所有后续动作的前提。
2. 简体中文一页说明，只讲本地路线：`npx octocrawl`，不依赖托管域名。
3. 如果可达：魔搭 MCP 广场（共 12,911 个服务器；分类里"文档访问"135 个、"浏览器自动化"611 个、"搜索"1,536 个；【推】类别数量小不等于竞争弱，也不等于有空位）。
4. 渠道：HelloGitHub 的月刊是 vfox 案例里真正的起点；V2EX 与 Linux.do 排在后面（这两个站的发帖规则以其社区为准，此前的计划提到 Linux.do 需要邀请，未核实）。**不用掘金**（NoteGen 作者说效果差）。
5. **先验证同一个假设**：Context7 跳过非英文页面。阿里云、飞书开放平台、微信小程序、腾讯云的中文文档，在 Context7 和 `llms.txt` 里的情况。
6. 网页存证（可信时间戳、哈希）是一个有法律钩子的细分：最高法《互联网法院审理案件若干问题的规定》第十一条要求互联网法院对经可信时间戳、哈希校验、区块链等手段认证并能证明真实性的电子数据予以确认（同条另列争议时的审查因素，所以有利于平台级取证，不是任意哈希）。但**价格和竞品都没找到**（调研 §5.2），先作为访谈问题，不做推广。

**不做。** 不做人民币定价，不承诺国内可用，不宣传"绕过拦截"。

**两周内的检验。** 可达性测试结果；中文一页说明的访问来源；是否有 1 个中国开发者愿意做一次访谈。

## 8. 风险

1. **托管直接抓取的法律姿态**（*Amazon v. Perplexity* 之后与本地 Chrome 不同）。推广托管版之前先问律师。
2. **增强访问与 MoR。** Polar 与 Paddle 的禁止清单里都有"使能未经授权访问他人数据"；Paddle 还点名验证码求解，并把"VPN 和代理"列为受限类别；Polar 没有点名验证码求解或代理；Octocrawl 的相关功能离这些词很近。写产品页和 MoR 申请时要如实描述，不要隐瞒（此前的 GTM 计划要求对 MoR 如实披露增强访问，这是当时的摘要，未重读原文）。
3. **Firecrawl 的 Alexandria** 覆盖文档、README、issue，可能与"文档楔子"重叠（调研 §4.6）。
4. **文档平台自己的受保护 MCP**（Mintlify 已核查，GitBook 未复核）削弱"登录后文档"的楔子。
5. **没有任何买家侧证据说明人们因可追溯而选工具**（调研 §5）。T5 的叙事先当假设。
6. **访谈样本小。** 3 到 5 个人的访谈不能推出比例。
