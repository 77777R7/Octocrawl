# Octocrawl 用户画像：五层阶梯（2026-11-09）

**状态：** 草案 v0.1，待 Howard 审定。本文只回答"谁是用户"，不加功能。它服务于 ROADMAP 当前阶段"十个外部用户"：每周那 10 条消息发给谁，第一批试用找谁。

**依据：** [市场调研记录](../../research/market/2026-11-09-global-market-research.md)（三轮调研；其中核查过的断言各由 2 到 3 个独立核查员回到原文核对，研究员读到但没有核查的线索在文中标明"未经核查员复核"），加上 Octocrawl 自己的托管漏斗（30 天，只读）。文中"调研 §x"指那份记录的章节。

**证据标注：**
- 【强】一手来源，核查员读到了原文，口径清楚。
- 【中】公司自报、二手转述，或口径不清（没有基数、定义含糊）。
- 【弱】只有旁证。
- 【未知】查过但没有找到。**未知不是零。**
- 【推】我们自己的推断，不是来源说的。

---

## 结论先说

1. **按"离工具有多远"分五层，越往下人越少、越贴近 Octocrawl。** 第 1 层是只和聊天助手说话的人，第 5 层是需要"每个数字都能追到原始页面"的团队。
2. **【推】入口是第 3 层，收入在第 4 层，护城河在第 5 层。**
   - 第 3 层（用编码 agent 的开发者）是现在的楔子，也是最容易被 MCP 目录和社区触达的一层。
   - 第 4 层（写 agent 和 RAG 的构建者）【推】最像 Firecrawl、Tavily 的付费用户（没有来源披露谁付费），也是静默失败这类痛点最集中的地方（公开案例只有三个，强度不一，不是比率）。
   - 第 5 层（要证据的团队）最契合 Evidence Record，但**目前没有任何来源证明有人因为"可追溯"而选工具**，是待验证的假设。
3. **第 1、2 层不是买家，【推】但它们可能是流量来源。** Octocrawl 最近 30 天 14 个外部注册里，5 个的首次来源是 chatgpt.com（另有 3 个 direct、6 个未记录），没有一个能确认来自编码 agent 社区；这 5 个人是不是 T1、T2，数据不能说明（调研 §1）。
4. **第一手数据否定了一个假设：** 30 天 7,437 次 MCP 连接来自 288 个客户端名称，排在前面的几十个大多是目录和探测机器人（也有 `mcp`、`coda-agent-runtime` 这类无法判断的通用名称）；没有一条 Cursor、Codex 或 OpenCode（调研 §1）。"编码 agent 开发者正在用 Octocrawl"目前**没有证据**，只是方向。

## 阶梯总览

| 层 | 名称 | 一句话 | 他们怎么接触 Octocrawl | 现在的适配 | 规模证据 |
|---|---|---|---|---|---|
| T1 | 对话用户 | 在网页或手机上和聊天助手说话，把链接贴给它 | 官网 Playground（每天 5 页）；ChatGPT 的回答里引到官网 | 低，不是买家，是流量 | 【强】基数很大：Reuters 九国每周使用 42% 到 68%（阿根廷 68%、挪威 57%、美国 49%、英国 42%），Microsoft 遥测（15 到 64 岁）在文中列出的国家里从 17.5%（中国）到 49.6%（法国） |
| T2 | 连接器用户 | 会在 Claude、ChatGPT、Le Chat、PlayMCP 里粘贴一个 MCP 地址，但不写代码 | 托管 MCP，无密钥，每天 20 页 | 低到中：能激活，几乎不付费 | 【未知】没有来源给出这一层的人数 |
| T3 | 编码 agent 开发者 | 每天用 Claude Code、Cursor、Codex、Copilot，自己改配置加 MCP | `claude mcp add`、`npx octocrawl`、MCP 目录 | **中到高：入口和楔子** | 【强】全球占比；【未知】分国家 |
| T4 | Agent 与 RAG 构建者 | 写代码调用抓取 API，批量灌知识库、做研究 agent | SDK、REST、crawl 与 batch 任务 | **高（【推】收入层）** | 【中】对手自报用户数以百万计 |
| T5 | 要证据的团队 | 下游会追问"这个数从哪来"，需要带时间和哈希的原始页面 | Evidence Record、批量任务的失败清单、本地 Chrome 读登录后页面 | **最贴合产品主张，但最未验证** | 【弱】只有邻近行业的旁证 |

【推】深一层并不自动等于更好的客户：层越深，人越少，销售越重，试错越贵。当前阶段的目标是"十个人完成一个真实任务"，所以**先在 T3 找人，同时盯 T4、T5 里已经有痛点的人**。

## T1 对话用户

**是谁。** 用 ChatGPT、Claude、Gemini、豆包、DeepSeek、Kimi、Naver 或 Kakao 系助手的普通人和职场人。不配置任何东西。会把一个链接贴进对话，让助手"读一下"。

**规模。**
- 【强】Reuters Institute 2026（每国约 2,000 人，在线调查）每周使用独立聊天机器人：美国 49%、法国 48%、日本 46%、英国 42%。（调研 §2）
- 【强】Microsoft AI Diffusion Report 2026 Q2（遥测，15 到 64 岁）：法国 49.6%、英国 43.7%、荷兰 43.5%、韩国 40.6%、加拿大 38.5%、美国 33.0%、德国 32.3%、日本 24.7%、中国 17.5%。这套数字**可能低估中国**：Microsoft 自己说部分国产工具没有覆盖，低估程度没有测。
- 【中】CNNIC 2026 年上半年：中国生成式 AI 用户超 7 亿，普及率超 50%（新华社转述，没有给分母和口径；上一份 CNNIC 报告的口径是"过去半年内用过"）。
- 这些是大众数据，**不能当成开发者、MCP 或抓取的代理指标**。这是第一轮核查员的提醒；Reuters 页面本身只提醒两个百分点以内的差异要慎读、在线样本会低估不上网的人。

**付费。** 【强】Reuters 九国平均 10% 自己付费使用 AI；日本 14%、美国 13%、英国 5%、法国 7%。付的是聊天订阅，不是抓取工具。

**对 Octocrawl 的意义。**
- 【弱】T1 的人不会装工具。他们的价值是**入口**：问助手"怎么抓网页""Firecrawl 替代品"的人，会看到助手引用的官网页面。
- 第一手：最近 30 天 14 个外部注册，5 个的首个来源是 chatgpt.com，3 个 direct，6 个未记录。chatgpt.com 是能识别的最大来源，但这 5 个人是不是对话用户，数据不能说明（8 个外部账号调用过托管 API，开发者也用 ChatGPT）。

**GTM 动作：** 不做付费获客。做 SEO 与 GEO（让助手引用到官网的正确页面）和 Playground。

## T2 连接器用户

**是谁。** 不写代码，但会点"添加连接器"，粘贴一个远程 MCP 地址。例如在 Claude、ChatGPT、Le Chat（Mistral）、Kakao PlayMCP 里添加一个能读网页的工具。产品经理、研究员、市场、运营、分析师。

**规模。** 【未知】没有找到任何来源给出"配置过 MCP 的非开发者"人数。**不要用 T1 的人数去估这一层。**
- 能确认的只有渠道：Kakao PlayMCP 到 2026-05 有约 200 个外部 MCP 服务器（【中】Kakao 自报）。Mistral 文档称可以把任何兼容 MCP 的服务注册为 connector，这条是研究员读取的线索，没有经过核查员复核，落地前要再读一遍原页面。

**触发时刻。** 助手自带的"联网"读不了某个页面（登录后、表格、PDF），他们想找一个能读的工具。

**对 Octocrawl 的意义。**
- 无密钥托管 MCP 每天 20 页，对这一层刚好够"试一下"。账号每月 1,000 积分。
- 【推】T2 的流失主要发生在配置那一步。一句话的接入说明和一个能成功的第一次调用，比功能更重要。

**GTM 动作：** 把 Octocrawl 放进各助手的连接器目录；接入文档写成一行命令或一个地址。

## T3 编码 agent 开发者（入口）

**是谁。** 每天用 Claude Code、Cursor、Codex、Copilot、OpenCode、Trae、通义灵码等工具写代码的开发者，会自己改 MCP 配置。

**规模。**
- 【强】Stack Overflow 2025（49,009 份回答，177 个国家，自选样本）：84% 使用或计划使用 AI 工具；专业开发者 51% 每天使用。
- 【强】同一调查里，回答"常用的开发环境和 AI 编码工具"这一题的 26,143 人中，Cursor 17.9%，Claude Code 9.7%，Windsurf 4.9%，VS Code 75.9%。
- 【强】JetBrains 2026（15,000 多名专业开发者，2026-05 到 07）显示同一系列里半年内的变化：工作中使用 Claude Code 39%（2026-01 为 18%，美国 47%），Codex 16%（1 月 3%），Cursor 12%（1 月 18%）。Stack Overflow 2026（30,903 份）：回答"过去一年用过哪些编码 agent"的 12,255 人中 Claude Code 65.5%、Copilot 58.7%、Cursor 25.5%；17,464 人中 26.2% 用"AI agent 或自动化工作流"，其中 63.1% 每天用。**Stack Overflow 2025 与 2026 问的不是同一道题、基数也不同（2025 是 26,143 人回答"常用的开发环境"），不能直接相减；两份调查之间也不能比。**
- 【中】Microsoft 2026-07-29 财报电话会：GitHub Copilot 有 5,000 万用户（"用户"未定义）。
- 【强】JetBrains 2025 中国专项：中国开发者里 Cursor 25%（全球 12%），Copilot 24%（全球 34%）；ChatGPT 和 Claude 的占比明显更低，DeepSeek 与通义灵码更突出。JetBrains 2026 显示中国的 Cursor 占比从 28%（2026-01）降到 16%（2026-05 到 07），降幅最大。
- 【中】Anthropic 2025-10：韩国的 Claude Code 周活用户四个月增长 6 倍；OpenAI Korea 2026-09：ChatGPT Work 与 Codex 的周活用户半年约 14 倍。**两条都没有基数。**
- 【中】日本有几份自选小样本：Findy（n=943）六成以上用 Claude Code；Offers（2025-03，n=208）63.4% 积极使用 AI 编码 agent；Qiita（n=2,317）64% 几乎每天用生成式 AI。
- 【未知】德国、英国、法国、荷兰、北欧各国使用编码 agent 的开发者占比。我们没有找到 Stack Overflow 公布的分国别 AI 使用率（它的数据下载没有读）。韩国也没有自己的连续调查。
- 【中】配置 MCP 的开发者占比：最大的两份调查（Stack Overflow 2026、JetBrains 2026）我们读过的页面里都没有这个问题。唯一的比例是 Postman 2025（5,700 多人，偏 API 从业者）：70% 知道 MCP，10% 经常使用。**知道的人是常用的人的七倍。**
- 可见的生态规模：官方 MCP Registry 约 5.2 万个服务器（第三方 2026-10-28 的计数），Smithery 20,759，PulseMCP 21,566，Glama 118,186；`@modelcontextprotocol/sdk` 单周 8,800 万次 npm 下载（含依赖安装，不是用户数）。PulseMCP 估计的每周访问：Playwright 550 万、Browser Use 110 万、Context7 100 万、官方 Fetch 22.7 万、Firecrawl 19.1 万。

**触发时刻（来自产品定位，【推】，还没有用户确认过）。**
1. agent 去读一个文档页，拿到的是空页面或登录墙。
2. Context7 没有收录这个库，或内容过期。
3. 答案需要引用确切的页面，而不是模型记忆。

**对 Octocrawl 的意义。**
- 入口命令：`claude mcp add --transport http octocrawl https://mcp.octocrawl.dev/mcp`，本地 `npx octocrawl`（可用本机 Chrome 读登录后文档）。
- 【推】这一层的人愿意为编码工具付月费，但**很少为 MCP 服务器单独付费**（没有来源直接说明这一点）；付费更可能发生在碰到额度上限或开始批量用的时候，也就是进入 T4。
- 【强】楔子的对手：Firecrawl 的 Alexandria 带一个开发者索引，称覆盖文档、README、issue 和已合并的 PR；Context7 从 GitHub 收录时跳过正文主要不是英文的页面（网站来源是否也跳过，没读到），私有来源需要付费套餐；文档平台 Mintlify 为认证站点提供自己的受保护 MCP（GitBook 同类，这一句未经核查员复核）（调研 §4.6）。【推】"登录后文档"不是没人管；"非英语文档"可能是一个更具体的缺口，要实测才知道。

**GTM 动作：** MCP 目录与官方 Registry、Show HN、Claude Code 和 Cursor 的社区、文档类使用场景的教程。**第一批 10 个试用者主要从这一层找。**

## T4 Agent 与 RAG 构建者（【推】收入层）

**是谁。** 写代码调用抓取 API 的人：
- 把文档站、博客、产品页灌进知识库做 RAG。
- 做研究 agent，需要读很多页面再综合。
- 做竞品、价格、招聘信息的数据管道。
- 做 AI 产品，需要"读网页"这个工具。

**他们今天用什么。** Firecrawl、Jina Reader、Crawl4AI、Tavily、Exa、Apify、ScrapingBee、ZenRows、Spider。

**规模（都是对手自报或包下载，不是用户数）。**
- 【中】Firecrawl 2025-08：35 万开发者注册；2026-09 称"超过 150 万用户"。GitHub 约 20 万星。PyPI `firecrawl-py` 30 天 594 万次下载（日序列求和），npm `firecrawl` 30 天 340 万次（含 CI 与镜像）。
- 【中】Tavily：自报超过 100 万开发者，2026-02 宣布被 Nebius 收购。
- 【强】这一层**已经被大钱占据**：Firecrawl B 轮 7,500 万美元（2026-09-22），Exa C 轮 2.5 亿美元、估值 22 亿美元（2026-05），Jina 2025-10 被 Elastic 收购。
- 【中】构建者的总量：LangChain 的调查（2025-11 到 12，1,340 份，自愿问卷）57.3% 的受访者已有 agent 在生产环境；Menlo（495 名美国决策者）说企业部署里只有 16%、创业公司 27% 算真正的 agent，多数是固定流程；GitHub 话题页上 `rag` 64,015 个公开仓库、`ai-agents` 138,904 个、`mcp` 116,792 个（会重叠）。
- 【未知】分国家的构建者人数。没有来源给出。Firecrawl 付费用户占比也没有披露。

**他们的痛点里，Octocrawl 的回答在于"记录里有什么"，不在于"不收费"。**
- 【强】"失败不计费"已经被多家宣称，不是独有卖点：Crawl4AI Cloud 官方写明被拦、登录墙、无应答都不收费；Firecrawl 对返回了文档的 403 和 404 仍收 1 积分，对 HTTP 200 的拦截页文档没写（调研 §4.5）。
- 【中】"静默失败"有公开案例，但强度不一：只有 Hermes Agent 一例是经核查的、被证明的静默失败（问题在集成层）；omnifeed 的 PR 是 PR 作者对 Crawl4AI 行为的说法，Oxylabs 是计费定义，并未测试"HTTP 200 加验证码页"：Hermes Agent 的 Firecrawl 集成在目标站拒绝时返回成功的空结果（issue 2026-08-31 提出，2026-10-28 修复）；据下游项目 omnifeed 的 PR，Crawl4AI 0.9.3 起 `/crawl` 在所有 URL 失败时仍返回 HTTP 200 和 `success: true`（2026-10-08 合并）；Oxylabs 的计费文档把 2xx 和 4xx 都算成功并计费。
- 【弱】以上说明痛点存在，**不说明人们会因此选工具**。没有找到把"诚实报告失败"当成购买理由的调查或采用数据。

**触发时刻。** 灌库的批量任务里混进了被拦的页面；账单里有失败的页面；需要在流水线里区分"页面本来就空"和"没读到"。

**对 Octocrawl 的意义。** crawl 与 batch 任务（每次最多 500 页或 1,000 个 URL）、失败页保留原因、JSON 字段带证据。
**GTM 动作：** 集成（Vercel AI SDK、Dify、n8n 一类）、"从 Firecrawl 迁移"的对照文档、公开的失败对照基准。

## T5 要证据的团队（最契合，最未验证）

**是谁。** 下游有人会问"这个数从哪来、什么时候读的、页面后来变了吗"的团队：

| 子类型 | 为什么需要证据 | 旁证 |
|---|---|---|
| 研究与尽调（金融、咨询、法务、学术） | 报告要引用，引用要可复核 | 【强】Zittrain 等 2014：哈佛法律评论等期刊 70% 以上的 URL，美国最高法院判决约 50% 的 URL，已不指向原引用内容（链接腐烂与内容漂移） |
| 合规留存 | 监管要求保留网页内容 | 【中】FINRA 通知 17-18：保留什么由内容决定，Rule 17a-4(b) 至少三年（研究员读取，未经核查员复核；是通用的留存义务，不是专门针对网页的规则） |
| 法务取证 | 要能在程序里作证 | 【中】Page Vault 外包抓取 199 美元起（网站）、349 美元起（社交主页）；日本的 ウェブ魚拓 批量抓取 1,000 页内 6 万日元，自称"被用于各种诉讼"；中国最高法的互联网法院规定要求法院对经可信时间戳、哈希校验等认证并能证明真实性的电子数据予以确认（同条另列争议时的审查因素） |
| 档案馆与图书馆 | 保存整站，长期保存 | 【强】卢森堡国家图书馆 2025-10-30 把网页存档合同（87.5 万欧元）授予 Internet Archive；爱尔兰国家图书馆 2026-08 招标（估值 32.5 万欧元），上一次也只有 Internet Archive 一个投标人。**买的是网页存档服务（公告全文没读到，具体形式不详），不是数据抽取** |
| 品牌保护与下架通知 | 向平台举证 | 【推】欧盟《数字服务法》第 16 条只要求通知写明确切 URL，不要求截图、时间戳或哈希；这一类需求没有被法规强制，不是 T5 的强需求 |
| 变化监测 | 竞品与价格变化要有凭据 | 【中】Visualping 自报"85% 的财富 500 强用过"，约 800 个工作区有 50 个以上监测，**没有付费客户数** |
| 数据代理与自由职业者 | 交付给客户的表要带来源 | 【中】Apify 自报 8 万客户、11.5 万个 Actor |
| 训练数据披露的 AI 公司 | 欧盟 AI Act 要求披露爬虫名称、抓取时段、前 10% 域名 | 【强】欧盟委员会模板；**没有找到这类公司购买第三方抓取证据的来源** |

**现有的第一手任务。** 仓库里已记录的真实任务是同一类：种子用户的数据中心公开来源表（[docs/guides/url-list-to-csv.md](../guides/url-list-to-csv.md)），每行都要能追到原页面。

**未验证的核心假设。**
- 【未知】有没有团队因为"带哈希和时间的记录"而选择工具、并为此付更高的价。关键证据（买家侧的采购、合同、访谈）**一条都没有找到**。
- 【未知】这一层的人数。没有任何来源。
- 【推】T5 里**有真实预算的是"留证据"这件事**（法律取证、档案馆、ウェブ魚拓），不是"数据抽取可追溯"。验证 T5 的办法是去问**现在为留存网页付钱的人**，看他们是否也有批量抓取和结构化的需求。付费点更可能是"一次性的、带证明的批量捕获"，而不是订阅。

**对 Octocrawl 的意义。** Evidence Record 是 Octocrawl 与对手的实质差别（失败如实标注、robots.txt 决定记录、内容哈希）。法律上，【强】美国联邦证据规则 902(14) 允许从设备、介质或文件复制的数据，经合格人员证明其"数字识别过程"后自证真实，2017 年的委员会说明称这类数据通常用哈希值认证；902(13) 对电子系统生成的记录同理；两者都要求按 902(11) 提前通知。这是哈希记录可能有用的法律基础，是否适用于具体案件要问律师。
**GTM 动作：** 不做批量获客。只做访谈：找 5 个有"被追问来源"经历的人，问他们现在怎么留证据（见文末问题）。

## 怎么验证这些画像：给 Howard 的访谈问题

每个人 20 分钟，一定先问"最近一次"，不问"会不会"。

1. **（T3）** 你最近一次让 agent 读一个文档页，拿到的是空的或被拦的，是什么时候？当时你怎么做的？
2. **（T3）** 你的 MCP 配置里现在有哪几个？哪个是你自己加的，为什么加？
3. **（T4）** 你上一次批量抓网页是什么任务？多少页？用什么工具？账单是多少？
4. **（T4）** 有没有一次工具说"成功"，后来发现内容是空的或是验证码页？你是怎么发现的？
5. **（T4）** 如果工具对每个失败页写明原因，并且不收费，这对你是"值得换"还是"锦上添花"？
6. **（T5）** 最近有人追问过你某个数字的来源吗？你当时拿出了什么？
7. **（T5）** 你现在怎么保存"当时那个页面长什么样"？花多少钱、多少人力？
8. **（所有人）** 你付过费的开发工具里，最后一个是什么，是谁批准的？

**判断标准：** 问题 1、3 的答案是"上周"或"这个月"，才算有真实痛点；问题 5、6、7 里出现具体金额或具体的人，才算 T4、T5 有付费可能。

## 国家与层级

分国家的规模、法律、渠道、支付和优先级见调研记录与 [分国家 GTM](2026-11-09-gtm-by-region.md)。这里只记画像在各国的主要差异：

| 地区 | T3 的特点 | T4、T5 的特点 |
|---|---|---|
| 美国与加拿大 | 编码 agent 与 MCP 的发源地；Claude 人均使用靠前（AUI 美国 3.62、加拿大 2.91；韩国 3.73、以色列 7 更高） | 对手最密集，融资最集中；加拿大另有 PIPEDA 对"公开个人信息抓取"的处理 |
| 中国大陆 | 无法直接使用 Claude；Cursor 占比高于全球（2025 年专项 25% 对 12%；2026 年 5 到 7 月 16% 对 12%，仍高于全球，但从 1 月的 28% 明显下降），DeepSeek 与通义灵码被 JetBrains 称作有重要地位（无数字），Trae 只有公司自报的全球 600 万用户 | 自有的 Dify、FastGPT 等栈；官方域名可达性、支付、备案都未解决 |
| 日本 | 内容社区成熟（Zenn MCP 话题 4,002 篇文章） | 著作权法第 30 条之 4 允许非享受目的的信息分析；它不管访问权限、服务条款和不正当竞争防止法 |
| 韩国 | 【推】非美国里最强的 Claude 与 Codex 增长信号（公司自报，无基数；没有来源作过这个比较；Anthropic 2026-06 把韩国的名次写作"前十几位"）；Kakao PlayMCP 是本地分发渠道 | 最高法院 2022 年判决：访问权限由服务商设定，限制用途的使用条款不等于限制访问；国内大站对海外 IP 的拦截只有厂商（HashScraper）一家之言 |
| 欧洲 | 德国、法国、英国、荷兰开发者基数大；Mistral 的 MCP connector（未复核） | TDM 退出机制与 GDPR 是最重的合规议题；数据驻留是采购问题 |

**这张表是方向，不是排名。** 排名和理由在 GTM 文档里，并且标明了证据不足的地方。
