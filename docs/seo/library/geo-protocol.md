# GEO 观测协议

状态：v0.1，2026-10-28 起草，**提议，未经 Howard 批准**。对应 [核心框架](../core-seo-framework.md) §4.8 与 §6。
依据：[GEO 研究记录](../../../research/seo/2026-10-27-geo-research.md)（下称「GEO 记录」，括号里写 G§n）。题库见 [geo-prompts.md](geo-prompts.md)。
方法借自一份外部的 GEO 观测方案（另一个产品团队的内部文档，不入库）：只借用整体思路（指标分主辅、固定题库、周度复查、缺口分类）。指标定义、规则措辞、数字和题目都按 Octocrawl 的证据另写，其中没有对方的原文。

## 0. 先说限制

1. **这套协议还没跑过。**唯一的基线是 2026-10-16 的一次 Google AI Mode 样本（已登录的会话；本协议要求未登录的临时对话，所以这份基线与之后协议采集的数据不可直接比较）：12 个固定问题，每题一次，6 个回答提到了 Octocrawl 这个名字，0 个引用了官方页面，并有实体、安装和 hosted 限制上的错误，包括把它说成 Octoparse（`docs/seo/ai-visibility.md`）。
2. **单次回答不能下结论。**同一个问题问两次，助手给出同一组品牌的概率不到百分之一（SparkToro 与 Gumshoe，2026-01，grade B，卖追踪工具的一方参与）；一项预印本研究里（St. Gallen，arXiv 2604.07585，未经同行评审；作者称数据公开，我们没有打开数据仓库核对；瑞士德语提示、4 个行业、45 天），同一天重复运行，品牌集合的 Jaccard 只有 0.375 到 0.492。（G§3.3）
3. **12 题单次样本的不确定性很大**：6/12 的 95% Wilson 区间是 25.4% 到 74.6%；0/12 是 0.0% 到 24.2%。所以它不能证明「官方页面不被引用」；内容改动后只有很大的变化（例如提名从 6/12 升到 12/12）才会让区间分开，小幅改进看不出来，区间重叠也不等于没有变化。单次回答之间的噪声（第 2 条）让即使很大的变化也只能算线索，要重复采集才能确认。（G§3.4）
4. **采集需要一个已登录的网页版会话，内置浏览器现在没有。**2026-10-28 的只读检查：内置浏览器能打开 chatgpt.com、claude.ai、perplexity.ai，没有被拦，但三个都没有登录（ChatGPT 与 Claude 跳到登录页，Perplexity 是未登录首页）；没有提交任何问题；我不能替你输入密码或注册账号（G§8）。2026-10-16 那次，已登录的 ChatGPT 对第一题返回 `Model not found`，未登录的 Perplexity 要求注册，每个只试了一题一次，推不出「现在还不行」。**没测过**：Claude in Chrome（你自己的 Chrome，登录情况可能不同）、未登录状态能否回答问题、内置浏览器的网络出口是不是美国。用你自己的账号采集时，要按 §3 用临时对话、关记忆与个性化，结果只代表没有历史的用户。另外，用 API 不等于用户看到的：中立研究发现 API 加 Google 只能复现 ChatGPT 网页版引用 URL 的 26% 到 28%（G§3.3）。仓库里起草的 sub-agent 也不能代替，因为它们读得到仓库里提到 Octocrawl 的指令，答案会被污染。
5. **没有可靠的数据集单独量过开发者工具或文档站**：已有研究量的是消费品、新闻、B2B 软件的混合样本。仅有的相关数字都不能用：ThriveStack 报告了 DevTools 行业 71.4% 的引用率，但该页自己的表里这 10 个品牌平均约 91.4%，两者对不上，没有原始数据，grade C；Digital Applied 的样本里有 25% 是开发者工具，但没有单独给出这一部分的结果，grade C；Liu 等人含 30 条技术文档类查询，但我们没有提取分类别的来源名单。把这些数字搬到 Octocrawl 身上是没有依据的。（G§3.2）

## 1. 要回答的三个问题

1. 用户中立地提问时，AI 助手会不会自然地提到、推荐 Octocrawl？
2. 提到的时候说得对不对：能力边界、hosted 与 local 的差别、有没有把它说成别的产品？
3. 助手引用了谁？引用的页面里有没有我们的？没有的话它在引用谁？

**不回答**：搜索排名、搜索量。那是 Search Console 的事（框架 §6）。

## 2. 指标

| 指标 | 定义 | 为什么看 | 数据怎么来 |
|---|---|---|---|
| **提及率**（主） | 提到 Octocrawl 的有效回答数 ÷「应提及」题的有效回答数；分平台、分模式（hosted 无 key / 需账号 / 仅本地）单独算 | 用户问「用什么」时，助手点不点我们的名 | 题库每周采集 |
| **推荐率**（主） | 选型类应提及题里，Octocrawl 被**列为推荐方案**（不只是被点名）的回答数 ÷ 选型类应提及题的有效回答数 | 点名不等于推荐 | 同上 |
| **引用率**（主） | 引用了 `octocrawl.dev` 页面的回答数 ÷ 有效回答数；每次记录是哪个页面。「点名但没引用」与「引用但没点名」分开记（一项 Semrush 研究里 61.7% 的出现是引用了却没点名，grade B） | 看哪些页面被助手用上了 | 同上，读回答里的来源 |
| **说对率**（主，我们特有） | 提到 Octocrawl 的回答里，该题「核对要点」（geo-prompts.md 末尾）全对的比例；错误按类记：当成 Octoparse、把 hosted 说成能读有防护页面、把仅本地能力说成 hosted、编造价格或付费计划、说成「能读任何站点」、其他 | 实体混淆已被观察到；说错比不提更糟 | 逐条人工核对 |
| **竞品提及份额** | 提到 Octocrawl 的次数 ÷ 提到任一同类工具的总次数；Firecrawl、Jina Reader、Crawl4AI、Apify 等并列 | 只看自己的提及率会随题集上下浮动，放在一起比才知道推荐位是在增加还是被别人拿走 | 同上 |
| **误提及率**（校准） | 「不应提及」题里 Octocrawl 被当作解决方案推荐的比例 | 看助手会不会夸大：这些题里 Octocrawl 做不了或不该做 | 同上 |
| **AI 来源访问到注册或首次调用的转化** | 来自 AI 助手的访问里，完成注册或首次调用的人数 ÷ 访问人数，分子分母同源（第一方分析） | 唯一能直接证明 AI 带来实际使用的数据，但只覆盖带来源信息的访问，是下限 | 第一方分析（G§5） |
| 辅助：被引用的第三方页面里已提到 Octocrawl 的占比 | 助手引用的第三方网页里，已经提到 Octocrawl 的页数 ÷ 被引用的第三方网页总数；没提到的加进外链与登记的候选名单 | 决定外链投向哪里（框架 §4.6） | 题库采集 |
| 辅助：页面侧报告 | Search Console「生成式 AI 表现」报告（AI Overviews 与 AI Mode 的展示，按页面、国家、设备、日期，自 2026-08-31 起对所有站点开放；官方帮助页只写了展示，没有写点击、查询或 API）；Bing Webmaster Tools「AI Performance」（Copilot 与 Bing 摘要里的引用数、被引页面、抽样的 grounding 查询，2026-02-10 起公测） | 唯一免费的官方页面侧数据；只覆盖 Google 与 Microsoft | 各自的后台（G§4） |
| 辅助：爬虫访问 | 服务器日志或 Cloudflare AI Crawl Control 里 `OAI-SearchBot`、`ChatGPT-User`、`Claude-SearchBot`、`Claude-User`、`PerplexityBot` 的访问 | 只能证明被抓取，不能证明被引用 | 日志或 Cloudflare（G§2） |
| 辅助：品牌搜索 | GSC 里 octocrawl 品牌词的展示与点击 | 被推荐的人常常之后自己去搜名字；目前**没有任何可见的品牌查询** | GSC |
| 辅助：自述来源 | 注册时问一句「你是从哪里知道 Octocrawl 的」 | 补上看不到来源的人（终端里用 coding agent 的开发者往往没有任何网页点击） | 要在注册表单加这一问，由 Howard 决定（见 §8 第 5 项） |

## 3. 采集协议

| 项 | 做法 | 依据与说明 |
|---|---|---|
| 平台与顺序 | 先 ChatGPT 与 Claude（claude.ai，开联网搜索），再 Perplexity，然后 Google AI Mode（已有基线）；Gemini 与 Copilot 之后。第二阶段加「coding agent 本身」：在一个干净目录里，不配置 Octocrawl，请 Claude Code、Codex、Cursor 回答选型题 | Octocrawl 的第一批用户用 Claude Code、Codex、Cursor（框架 §1）；首个外部注册来自 chatgpt.com（n=1，原因未知，只作旁证；平台顺序主要依据第一批用户在哪里）；各平台的引用来源差别很大（G§3.2） |
| 界面 | 网页版或应用，不用 API；如果某次用了 API，结果要标明，不与网页版合并 | G§3.3 |
| 会话 | 每次新开临时对话；关闭记忆与个性化；开启联网搜索；记录网络出口地区与是否登录。**结果只适用于「没有历史的用户」** | 个性化会改变推荐集合（一项自发表研究量到 +1.0 到 +33.3 个百分点，grade B，只能当线索）（G§3.3） |
| 题集 | **核心集 28 条**（geo-prompts.md 里标「核心集」）每周；全库 124 条每月或接入工具后每周 | 手工问 28 条 × 3 次 × 3 个平台约 250 次，一个人每周已经很重；先小后大 |
| 次数 | 每条每平台每轮 3 次起步，**只作线索**。判断变化要在**题组层面汇总**并带区间：3 次读数的区间宽 64 到 75 个百分点，10 次 39 到 53，30 次 22 到 34，100 次 12 到 19（G§3.4，下限）。St. Gallen 预印本（未经同行评审，数据仓库未核对）建议同一题每天至少 7 次、持续 2 到 4 周，约合每题每周 49 次，是这里每题每周 3 次的约 16 倍；它自己说 7 次只能区分差别很大的品牌，不能给相近的品牌排序。两周试点（G-12）达不到这个量，只能粗略估计方差与人力，不能作严肃判断 | 能力不变时，同一条 prompt 的重复运行也很不稳定 |
| 问法变体 | 一个意图以后加 2 到 3 种问法；同一意图改写后的结果重合只有 0.14 到 0.29，远低于同一问法重跑的 0.50 到 0.61 | G§3.3；题库现在每个意图只有一种问法，要在第二版补 |
| 无效运行 | 平台故障（报错、超时）造成的失败回答不计入分母，重跑；助手正常答完但没有推荐 Octocrawl 的，计为未推荐 | 避免把平台故障当成我们的表现 |
| 每条回答记录 | 日期；平台与模型显示名；是否联网；网络出口与登录状态；prompt ID；第几次；完整回答；提到的产品及顺序；是否提到、是否推荐 Octocrawl；对它的具体描述；引用的链接；核对要点结果 | 复现与复查的最低要求 |
| 存放 | 每轮的汇总写成带日期的记录放 `research/seo/<日期>-geo-run-<平台>.md`；原始回答放 `.w2l/seo/geo-runs/`（git 忽略） | 记录一旦写完不再改（AGENTS.md） |

## 4. 每周复查循环

1. **观测**：核心集 × 各平台 × 3 次，按上表记录。
2. **判断**：提到了就逐条核对「核对要点」，说错的进入第 5 步；应提及却没提的进入第 3 步；本来不该提的只记录。
3. **追问找缺口**：在同一个对话里问「你是按什么条件挑这些产品的、参考了哪些来源、为什么没有选 Octocrawl」。助手的解释只当线索，要自己去看它引用的页面和我们现有的页面，确认到底缺什么。**追问得到的回答不进入任何指标。**
4. **补内容**：按缺口类型补到对应位置（下表）。同一块内容同时解释多条 prompt 的缺口时，写一份覆盖它们的内容；不按 prompt 逐条各写一份。
5. **下周复测**：同样的 prompt 与设置再问一遍。内容发布后至少隔一个完整采集周期再比较；这之前的回答只记录，不算效果。

| 缺口类型 | 怎么看出来 | 补到哪里（对应框架） |
|---|---|---|
| 官网没写清 Octocrawl 能做这件事 | 助手认为做不了，或根本没把它列为方案，而官网上找不到相关说明 | 对应的用例页或 docs（框架 §4.2） |
| 有能力说明但缺具体做法 | 官网提到了这个能力，没有步骤、配置或可照做的例子 | 接入页与教程（框架 阶段 1） |
| 缺少可信的实测 | 助手比较产品时引用别家的评测，或说找不到 Octocrawl 的实际表现 | 一手评测。仓库里已有 PA 的真实站点记录；发布哪一组、怎么标范围，等 Howard 决定（框架 §8.1 第 2 项）；必须含我们输的项（政策 G7） |
| 推荐来源里没有 Octocrawl | 助手引用的榜单、对比文章、讨论里都没有 Octocrawl | 外链与登记（框架 §4.6）；榜单类页面没有提交入口，登记处与生态目录有 |
| 说错了 | 对能力、hosted 与 local 差别、价格的说法有误或过时 | **第一步修正我们自己的官网页面和 `llms.txt`；之后再去纠正登记处描述、awesome 列表等第三方来源里的错误说法** |
| 确实做不了 | 核实后产品没有这个能力 | 记入产品需求，并把这条 prompt 改为「不应提及」；**不用调整营销措辞去换取提及** |

## 5. 规则

1. prompt 里**不加品牌名**，更不能为了提高提及率而改 prompt。
2. 追问得到的回答不进入提及率、推荐率、引用率。
3. 同一条 prompt 要连续多周对比，不凭一次回答下结论；连续几周没变化时，重新判断这条 prompt 该不该提到 Octocrawl，或我们补的内容够不够。
4. 产品能力变了（例如 hosted 上线 Monitor），回到题库复审「应提及」「模式」「核对要点」三列。
5. 我们自己不写脚本去自动提问助手的网页界面（违反多数服务条款，也会被拦）。用官方 API 做的补充测量要标明是 API，且 API 结果不等于用户看到的界面（§0 第 4 点：只能复现 26% 到 28% 的 ChatGPT 网页版引用 URL）。第三方追踪工具是否替我们抓取网页界面，要在采购前问清；用了抓取界面的工具，等于把这条规则交给了供应商，这个风险要由 Howard 接受（§8 第 1 项）。
6. 不在第三方站点发布虚假或误导的内容去影响 AI 的引用，也不付费买「GEO 发帖」服务。研究显示这类操纵确实有效（例如一项对 10 个平台的研究里，8 个在一周内引用了一个捏造的概念，grade B），但它与 Octocrawl「来源可追溯」的主张相冲突，也触碰搜索引擎的垃圾内容政策（政策 G14、G15、G19）。
7. AI 参与起草的页面要有一个人跑过命令、核对过断言（政策 G9）。
8. 不用「写给 AI 看」的隐藏文字或只给 bot 的内容（政策 G15）。

## 6. 站点侧检查项

分三类。「前置条件」不满足就谈不上被引用，先核对；「可选改进，效果未证」没有证据说它能提高提及或引用，是否做由决定 G-13 定，不是测量的前提；「测量来源」是读数的出处，不是站点要改的东西。

| 检查项 | 类型 | 现状 | 来源与说明 |
|---|---|---|---|
| `robots.txt` 不拦 `OAI-SearchBot`、`ChatGPT-User`、`Claude-SearchBot`、`Claude-User`、`PerplexityBot`、`Googlebot`、`Bingbot` | 前置条件 | 通过：`User-agent: *`、`Allow: /`、`Disallow: /api/`（2026-10-28 读取） | G§2 |
| CDN 与 WAF 不拦这些爬虫的官方 IP 段 | 前置条件 | **未知**。2026-10-16 的记录显示 7 天内有 10 次已验证的 AI 助手请求被拦，之后加了一条例外规则；没有更新的读数 | 读 Cloudflare AI Crawl Control 的分析页或日志 |
| Cloudflare 的 AI 爬虫设置没有误伤搜索爬虫 | 前置条件 | **未知**。Cloudflare 自 2026-09-15 起，对「训练」选 Block 会连 Googlebot、Bingbot、Applebot 一起封；只想拒绝训练用 Disallow AI Training | G§2 |
| 对 `Accept: text/markdown` 返回 Markdown | 可选改进，效果未证 | **没有**：`/`、`/docs/`、一篇博客对该请求都返回 HTML。`.md` 孪生页有，且带 `Link: rel="canonical"` | 2026-10-28 实测（G§8）。Claude Code 的 WebFetch 文档写明会发这个 Accept 头并自报 `Claude-User`，Anthropic 与 Cursor 的文档站做了协商，OpenAI 的不一致（一个文档站返回 Markdown，另一个返回 HTML，n=2）。只有 Claude Code 的文档写明会发该 Accept 头，而 WebFetch 自己会把 HTML 转成 Markdown，所以返回 HTML 也能读；没有官方说明说 Claude Code、Cursor、Codex 或 ChatGPT 会读 llms.txt 或该 Link 头，也没有研究显示协商会提高提及或引用。成本低、同类官方文档站已做，所以列为待决 G-13 |
| `Link: rel=llms-txt` 响应头 | 可选改进，效果未证 | **没有** | 同上 |
| `llms.txt` | 可选改进，效果未证 | 有，开头对 hosted 范围的描述是对的 | Google Search 忽略它；价值在别的读取者，不要把它算成 Google 的 SEO 工作（G§2） |
| Search Console「生成式 AI 表现」报告 | 测量来源 | 已读过一次：2026-09-16 至 10-13 共 2 次展示，都在 `/blog/scrape-list-of-urls/`；前一窗口为 0。该报告只给展示，按页面、国家、设备、日期拆分，没有问题文本、引用或品牌提及。之后的窗口没读，需要按周重读 | `docs/seo/ai-visibility.md`、G§4 |
| Bing Webmaster Tools「AI Performance」 | 测量来源 | 2026-10-28 读过一次（Howard 导出）：2026-10-07 至 10-25 共 19 天，Citations 和 Cited Pages 每天都是 0；导出里没有页面和查询表，0 是没被引用还是还没采集，分不出来。Bing 站点已验证；公测中 | G§2、G§4 |
| 第一方分析抓到首访的完整信息 | 前置条件（归因） | 部分：R5 闸门已加首次接触来源，第一个外部注册带 `utm_source=chatgpt.com`（n=1，原因未知）。要保证落地 URL 完整查询串、`document.referrer`、UA 类别、时间戳在跳转前存下来并带到注册 | G§5 |
| 每天检查「来自 chatgpt.com 的访问里带 `utm_source=chatgpt.com` 的比例」 | 前置条件（归因） | 未做。ChatGPT 的标记在 2026-10-08 至 16 前后消失过约八天（一家厂商的测量，grade B），访问变成直接访问 | G§5 |

## 7. 基线（2026-10-28 之前所有已有的）
