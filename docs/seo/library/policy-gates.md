# 发布闸门（来自搜索引擎官方政策）

状态：**提议，未经 Howard 批准**，v0.1，2026-10-27。规则来源与原文位置见 [研究记录](../../../research/seo/2026-10-27-core-seo-framework-research.md) §9；下面 20 条闸门是调研 agent 从官方规则推出的内部测试，**不是来源原文，也没有被验证过**。
框架 §4.3 引用 G1 到 G3（证据页）、G7（对比页）、G14（外链）、G20（不抓 Google 结果）。批准前，它们只作为写页面时的检查清单。

维护：官方政策变了，新增一份带日期的研究记录，再来改这里。没有数字阈值的地方（例如「先发约 5 页」）是内部提议。

| 闸门 | 适用于 | 测试 |
|---|---|---|
| G1 Unique evidence per page | scenario ('scrape <site>') pages | Each page in a batch has its own recorded run: command, source commit, run date, whether proxied or direct, and the real Evidence Record fields (final URL, status, robots decision, content hash). No two pages in the batch share the same result table. Fail if a page's body is the same as another's after the site name, URL and numbers are swapped. The sentence-overlap threshold is an internal choice (for example, reject if more than half the sentences also appear on another page of the batch); Google gives no number. |
| G2 Small-batch pilot before scale | scenario pages and any other programmatic family | Publish at most a small first batch (internal proposal: about 5 pages) and check Search Console after several weeks for indexing and impressions on those URLs before adding more. Any batch where most pages sit in 'Crawled - currently not indexed' or 'Discovered - currently not indexed' stops the family. Basis: Google applies the domain's overall quality to new pages, and Google gives no safe page count. |
| G3 Honest outcome on hard sites | scenario pages and tutorials | If the run for a site returned blocked, empty, wrong or partial content, the page says so using the status/blockReason in the Evidence Record and still counts in the batch. No page claims Octocrawl can read a site it has not read in a recorded run. No wording like 'works on any site'. No page tells readers to bypass CAPTCHAs or consent walls. Basis: misleading functionality policy. |
| G4 Reachable by hierarchy, not by query | scenario pages, comparison pages | Each page is linked from a hub page and a category page by crawlable <a href> links, and has a distinct user task, not just a distinct query phrase. A page fails if its only purpose is to send visitors to install or signup, or if two pages answer the same task under different keywords (merge them). Basis: doorway abuse, fan-out warning. |
| G5 No target lists or stuffing | all pages | No block listing many sites, cities or keywords, and no repeated exact phrase in an unnatural way. Read the page aloud; if a section exists only to hold keywords, remove it. |
| G6 Excerpt-only use of third-party content | scenario pages, tutorials | Pages show Octocrawl's output (hashes, field names, short excerpts) and never reproduce a target page's full text or large parts of its documentation. Check that quoted third-party text is short and attributed. Basis: scraping and scaled-content policies. |
| G7 First-hand comparison | comparison pages (Octocrawl vs Firecrawl and others) | The page states the competitor version tested (the repository freezes firecrawl-js v4.42.0), the test inputs, the date, the command, and the result for both tools, including cases where Octocrawl loses or cannot read the page. Every competitor claim not tested by us links to the competitor's own page with a fetch date. Fail if the table is copied from the competitor's marketing page or has no losing row for Octocrawl. |
| G8 Link qualification | comparison pages, tutorials, any page with outbound links | Any paid, sponsored, affiliate or reward link carries rel=sponsored (or nofollow); any user-contributed link carries rel=ugc. Search the built HTML of the batch for outbound links and confirm each one is either editorial (no rel needed) or correctly qualified. Fail if there is a monetary or free-product arrangement without disclosure and rel. |
| G9 AI-assisted content review | tutorials, comparison pages, scenario pages, tool pages | A named person has run every command or checked every claim; titles, meta descriptions, alt text and JSON-LD were also reviewed by a person; a real byline and an About page exist; no invented author, headshot or credential; the page says where automation was used if a reader would reasonably ask. Fail if any command in the page was not run, or if numbers have no recorded run behind them. |
| G10 Tool pages must work | free tool pages | On a clean browser profile, the tool completes its stated job on a sample input without login, and the result matches the page's promise. Fail if the tool fails, only redirects to signup, or relies on a bot-defended target in its demo. Also check that the page has useful text around the tool (what it does, limits, example output), not only a form. |
| G11 Structured data accuracy | all pages with JSON-LD | Every JSON-LD property is visible on the page or true of the page; validated by the Rich Results Test; no FAQPage markup added for rich results (feature gone since 2026-05-07); no aggregateRating or review unless real, visible user reviews exist; SoftwareApplication offers.price is 0 only where the tool is free as displayed; markup is the same across duplicate pages. Fail on any templated rating. |
| G12 Sitemap hygiene | sitemap.xml and any sitemap index | Only canonical, indexable, 200-status, absolute URLs; UTF-8; at most 50,000 URLs and 50 MB uncompressed per file (index above that); lastmod changes only when main content, structured data or links change; priority/changefreq are not relied on; removed pages are dropped and return 404 or 410. Run a script over the built sitemap that checks status, canonical and noindex for every URL. |
| G13 IndexNow discipline | IndexNow submissions | Submit only URLs that passed gates G1 to G12; only new, changed or deleted URLs; at most 10,000 URLs per POST; the key file is served at the host root; the same URL is not resubmitted within 5 minutes (10 after a 429); responses are logged. Fail if the whole site is re-submitted on a schedule without a migration. Remember IndexNow reaches Bing and its partners, not Google. |
| G14 Backlink and directory plan | directory submissions, outreach, guest posts, partner pages | Each target is a curated, editorial listing the team would be comfortable disclosing to a search-engine rep; no payment or goods for a ranking link without rel=sponsored; no automated posting or link-building tools; no reciprocal 'partner' page made for linking; no widget, badge or footer link distributed with keyword anchors; no requirement that others link to us; listings are added gradually, not in one-day bursts (Bing's link page says a sudden jump looks bought). Record each placement with URL and date. |
| G15 No cloaking via AI or Markdown variants | llms.txt, Markdown mirrors, content negotiation for agents, bot-specific responses | Any alternate version (llms.txt, .md copy, agent-specific response) contains the same substantive claims as the HTML page that users and Googlebot see, with no text served only to bots or only to agents. Never tell AI models what to say about Octocrawl. Treat llms.txt as optional and not an SEO deliverable. The official pages I read do not discuss Markdown content-negotiation, so this gate is a conservative reading of the cloaking and Bing prompt-manipulation policies. |
| G16 No hidden text or links; key answers visible | all pages | No text or links hidden by CSS, off-screen, zero font size, or colour match. Accordions and tabs are acceptable to Google, but the main answer to the page's question is visible without a click (Microsoft advises this for AI answers). |
| G17 Unique titles, one topic, early answer | all pages | Unique <title>, H1 and meta description per page, accurate and not exaggerated; one primary topic per URL; the answer or key fact appears near the top; one canonical URL per piece of content; dates only change when the page changes substantially. |
| G18 Crawlable and indexable | all pages | Robots.txt, CDN and Worker rules allow Googlebot and Bingbot; the page returns 200 with text in the initial HTML or in rendered HTML visible via the URL Inspection tool; not noindex; snippet allowed. Pages that return soft-404 'no data' content must return a real 404 or be removed. |
| G19 No third-party hosted SEO content | blog, tools, any future guest or partner section | Content on octocrawl.dev is written or editorially owned by the Octocrawl team; any sponsored or partner piece is clearly marked, integrated, and has rel=sponsored links; user-generated areas have spam controls and ugc links. Do not move failing pages to a new subdomain or domain to keep publishing them. |
| G20 No automated queries to search engines | research scripts, scenario pages about scraping search results, rank-check features | No script or demo sends automated queries to Google Search without express permission. Search demand data comes from Search Console. A tutorial about scraping SERPs is reviewed against the machine-generated-traffic policy and the engine's Terms before publication. |

## 已有的自动检查（2026-10-28）

闸门本身仍是提议；下面三项是 Howard 要求补上的检查，已经在跑，范围写在这里，没覆盖的不要当作已检查。

| 闸门 | 检查 | 覆盖 | 没覆盖 |
|---|---|---|---|
| G12 | `scripts/seo/check-sitemap.mjs`，CI 在构建站点之后运行 | 地址绝对、同一来源、带斜杠、不重复、无查询串；lastmod 是合法日期且不晚于明天的 UTC 日期（和 `docsPages.test.ts` 一致；没有 lastmod 的页面计数、不判错）；每个地址有构建出来的页面，页面有且仅有一个等于自身的 canonical、没有 noindex 或 none（robots、googlebot、bingbot 的 meta 标签）、有标题与描述；可索引的已构建页面必须在 sitemap 里；robots.txt 必须存在、指向 sitemap，并且对 `*`、Googlebot、Bingbot 都不禁止其中的路径（Allow 与 Disallow，支持 `*` 与 `$`，最长匹配优先）；单文件不超过 50,000 条、50 MB | 线上经 CDN 的真实状态码与响应头（包括 `X-Robots-Tag`）；其他爬虫的 robots.txt 规则；已删除的页面是否返回 404 或 410；「lastmod 只在主要内容变化时变」（docs 页由 `docsPages.test.ts` 保证；其他页面我没有找到对应的测试） |
| G13 | `scripts/public-preview/indexnow.mjs` | 只发新增或有变化的地址（比较 sitemap 的 lastmod，没有 lastmod 的页面比较其 Markdown 副本的哈希），被 sitemap 去掉且返回 404 或 410 的地址按删除发；每次 POST 不超过 10,000 条；同一地址 5 分钟内不重发（`--all` 与删除通知不受此限）；429 之后 10 分钟内什么都不发；202（密钥验证待定）记为未确认、下次再发；Markdown 副本暂时读不到时保留上次记录的哈希，不因此重发；每次响应写进日志 | 「只发通过 G1 到 G12 的地址」（部署后手工运行，没有检查）；「不按计划重发整站」（现在没有任何定时运行，所以没有可检的；第一次运行没有状态，会发一次整站；`--all` 会重发整站） |
| G11 | `scripts/seo/check-jsonld.mjs`，CI 在构建站点之后运行 | 已知的页面族（首页、docs、博客文章、博客总览、工具页、changelog）仍带各自的结构化数据；每个 JSON-LD 块能解析；顶层对象是本站在用的 schema.org 类型（新类型要显式加进允许表）；没有 aggregateRating、review 之类的评分与评论；地址类字段（url、@id、item、image、logo、sameAs、mainEntityOfPage 等）在本站同一来源（它点名的文件在构建里存在）或在允许的外部主机（github.com、schema.org）；`url` 与 `mainEntityOfPage` 等于页面的 canonical；TechArticle 与 BlogPosting 的 headline 等于本页面包屑的最后一项或在本页的 h1 里，description 等于 meta description，BlogPosting 的日期合法、先后正确、与文章 meta 标签一致；FAQPage 只允许出现在现在已有的两页（`/`、`/scrape/`），且每个问题与答案开头都在页面正文里；BreadcrumbList 的序号是 1 到 n、从首页开始、到本页结束、各项是已构建的页面 | 数据里的说法是否属实（只查它重复的页面信息与页面一致）；Rich Results Test（要线上站点）；description 只与 meta 标签比较，不是可见文字；新增的页面族没有结构化数据时不会报错，要先加进 `requiredTypes`；现有的两个 FAQPage 在 2026-05-07 之后不再有富结果（G11 原文），保留与否待 Howard 决定 |
