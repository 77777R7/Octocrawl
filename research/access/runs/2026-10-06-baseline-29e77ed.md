# Access task set baseline (G0), frozen 2026-10-06

The access task set (`research/access/tasks.v1.json`) is frozen from two runs on different days. Every later PA comparison counts against it: G1 (browser-compatible HTTP), G2 (egress sessions) and the experiments. No URL is replaced or dropped from here on; failed, blocked and unstable tasks stay in every denominator.

The second window deliberately did not use current main, which by then included G−1b, the PerimeterX gate, E0 and G1, so that the two windows differ only in the day.
- **One exit.** Both windows ran through one local proxy exit. The exit address was not recorded in window 1, and it was left out of window 2 on purpose, so the committed record does not publish the proxy exit. A task can pass through one exit and fail through another; nothing here covers another exit.
- **Cost columns read unknown.** This code predates G−1b, under which local lanes record a third-party cost of 0.

## What later comparisons use, and the latency limit for G1

- **The task file:** a later route runs the frozen, healthy, unstable and blind tasks of this file, and is judged with the same predicates.
- **What G1 must show (unchanged):** on the frozen set, in two time windows, more verified tasks than the current ladder, listed task by task. No healthy task may be lost, and the health suite must have no regression.
- **What G1 compares against:** current main with the compatible transport off, run at the same time on the same commit. This baseline's own numbers come from older code, so G1 is not compared with them directly.
- **Proposed latency limit, to be confirmed:**
  - **Window noise is too large for a cross-window comparison.** The two windows' p50 differs by 17% on the healthy tasks and 33% over all tasks, with the same code and the same exit.
  - **So the limit is a paired, same-window measure.** In one window, run each task the compatible rung serves with the transport off and on, interleaved. Take each task's wall-time ratio over the attempts both arms verified. G1 passes the latency part when the median ratio is at most **1.20**, that is at most 20% overhead at p50.

## Not covered

- **Tasks behind a login:** no test account, so not covered.
- **More than one exit, or a residential exit:** not covered.
- **The healthy tasks from the parity suite:** they are not repeated here. That suite runs `research/parity/run-sites.mjs`, and the Patchright A/B ran it four times on 2026-10-05 (`2026-10-06-patchright-ab-f052375.md`).
