# Patchright A/B: access task set and health suite, 2026-10-05/06

Question: does the public browser rung on Patchright (`W2L_BROWSER_ENGINE=patchright`, ADR 0005 `enhanced_browser`) reach pages that stock Playwright does not, without losing any it reaches? Rule set before the runs: Patchright goes forward to G5 only with a net gain of verified tasks on the blind set and zero regressions on the health suite.

Answer: no reproducible difference in either direction. On the access task set, Patchright gained one task and lost one; neither result held on recheck. The blind set showed no gain. The health suite showed no regression. The rule is not met, so Patchright is not adopted; the switch stays an opt-in experiment.

## Setup

- Two local APIs, both built from source commit `f052375` (main, with E0 merged). They ran side by side as `node packages/api/dist/cli.js`. The run records mark the tree dirty because the runner files under `research/access/` were uncommitted.
  - **A, port 8797:** stock Playwright 1.62.1, Chromium 151.0.7922.34 (headless shell build 1234).
  - **B, port 8798:** Patchright 1.63.0, Chromium 153.0.8010.12 (build 1243), with `W2L_BROWSER_ENGINE=patchright` and a grant that names `enhanced_browser`. Only the public browser rung changes; the http rung is the same on both.
- The two arms therefore differ in driver and in Chromium build. The driver × build check below separates the two for the tasks that differed.
- **Network:** both APIs and both runners were proxied through `HTTPS_PROXY`/`HTTP_PROXY=http://127.0.0.1:7890`, with `NO_PROXY=localhost,127.0.0.1,::1`. That is a single exit; the exit address was not recorded.

In every attempt, on both engines, T051 was blocked (`cloudflare_challenge`) and T053 was blocked (`bot_detected_generic`). Neither the gain nor the regression held.
- **Driver × Chromium build, outside Octocrawl (2026-10-05 18:44:43–18:45:40 UTC).** The same two URLs were loaded twice in each of the four combinations of driver (Playwright, Patchright) and build (1234, 1243), through the same proxy, using a local diagnostic script (`.w2l/access/tools/factorial.mjs`, not committed). ## What this shows, and what it does not

- Every page Octocrawl did not get here failed on both engines when checked again. These sites rule on the connection and the address (a 403 before any page script ran, the same over one exit for every driver and build), not on what the browser driver exposes. That points the next steps at G1 (browser-compatible TLS on the HTTP rung) and G2 (egress sessions), not at the browser driver.
- **Single exit:** with another exit or a residential address, the engines might differ. That was not tested.
- **Unfrozen task set:** this was the G0 candidate list; the frozen set and its second time window come later.
- **Mixed arms:** the arms differ in Chromium build as well as driver. The driver × build check covers only the two tasks that differed.
- **Latency:** Patchright's lower p50 and higher p95 on the access set are from 184 attempts per engine over one exit, and were not checked for significance.
