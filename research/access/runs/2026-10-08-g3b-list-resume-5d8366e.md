# G3b real-site run: a list task cut at page N resumes there, one window (2026-10-08)

ROADMAP PA item 3, after the first G3 run ([2026-10-07-g3-sessions-egress-0f1bf8f.md](2026-10-07-g3-sessions-egress-0f1bf8f.md)) listed "page N inside a list step" and "session and egress fields in the access block" as gaps. Both are now on `main` (PRs #278, #279, #281; #280 for the egress follow-ups) and this run shows them on two real paginated sites, through the egress pool. Three batches, one window, source `5d8366e`.

## How it was run

- 2026-10-08 09:57–10:01 UTC, source `5d8366e` (clean), one local API on port 8797, fresh task root, `W2L_ACCESS_GRANT={"tier":"standard","capabilities":["egress_sessions"]}`, `W2L_PER_HOST_CONCURRENCY=1`, browser lane (Chromium) for every page since the request has actions.
- Proxied through the pool only: `HTTPS_PROXY`/`HTTP_PROXY` unset for the API, `W2L_EGRESS_PROXIES=http://127.0.0.1:9,http://127.0.0.1:7890` (a port nothing listens on, then the machine's forward proxy; the same two as the first G3 run).
- Each batch: `POST /v1/batches` with one URL, `maxAge: 0`, `formats: ["markdown", {type: "list", itemSelector, fields}]` and one `paginate` step, the same requests as the parity cases LR03 and LR02 (`research/parity/sites.v1.json`), `timeout` 240 s / 180 s.
- The interruption: a driver polled the task's `checkpoint.sqlite` every second and sent SIGTERM to the API once `list_pages` held N rows for the URL; it then started the API again on the same task root and waited for the batch to end. Checks from `GET /v1/batches/:id/items?debug=true` (`list`, `actions.lists`, the `list_resumed` trace, `evidenceRecord.access`), and from `checkpoint.sqlite` (`attempts`, `steps`, `list_pages`).
- Raw outputs, the driver and the API log: `.w2l/access/runs/2026-10-08-g3b-5d8366e/` (not committed).

- A and C agree on every count: a cut at page 8 and a restart gave the same 582 records on 24 pages as the uncut run. B agrees with the parity expectation for LR02 (100 records, 10 pages). No record was lost or counted twice: every record's values are distinct, and each page is the source of its own records once.
- The resumed pages were all known again by their content (`knownBy.content`), none by their links or address alone, on both sites. The walk back along the site's own Next links to page N+1 is visible in time: A took 85 s end to end (23 s before the cut, 3 s of shutdown, about 58 s after the restart, of which the first 8 pages were passed over) against 59 s for C.
- `list_pages` was empty for every URL once its step was stored.
- Access fields (PR #278): every item carries `access.egress = {proxy: "127.0.0.1:7890", source: "pool", switchedFrom: …}` and `access.session = {id}`. Run C, whose only attempt took the dead egress first, shows `switchedFrom: "127.0.0.1:9"`; A and B were read again after the restart on the egress their task had kept (`egress.json`), so their stored page shows `switchedFrom: null`, and the switch of their first attempt is not on the stored result (that attempt stored no step).
- The egress follow-ups of PR #280 did not come up on these sites: no page was refused before its request, and no webhook or stream watched the terminal event. Their tests stand for them.

## Not covered

- A check met inside the list (PR #281, ListStop `challenge`): neither site puts one up. No real site with a challenge in a paginated list was in this window.
- The continuation after a check is handled ("handed to the person, verified at page N, continues") is not built.
- Lists whose pages share one address (an in-place pager) and lists whose rows carry no links: both sites here have addressable pages and linked rows, so the checkpoint's content keys were enough. The in-place and no-link cases are covered by the local fixtures in `packages/bench/test/listFormat.integration.test.ts` only.
- Several real exits, the cooldown's end, a logged-in list: as in the first G3 run.

## Verdict

The "resumes at page N with no lost or duplicated records" clause of item 3 holds on these two sites at the page level of a `paginate` step, through a real proxy, with the cut taken where the clause names it. Item 3 as a whole is still open on the challenge continuation and on several real exits.
