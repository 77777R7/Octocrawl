# Login UX A1 + A2 in a real Chrome, 2026-11-08

How many times does a person click to let a local server read sites in their own Chrome, with A1 (remembered sites) and A2 (one connection for the server's life)? Task list: `docs/login-ux-tasks.md`, A1 and A2.

## Setup

- Source commit: `61196aa0` (branch `claude/login-ux-a2-one-connection`, PR #897, on top of A1 `0da535ee`, PR #896). Neither is on main yet. `npx tsc --build` run before the server started.
- Server: `W2L_SESSIONS_FILE=<scratch>/sessions.json node packages/cli/dist/cli.js serve --port 8793 --task-root <scratch>/tasks`, loopback, started with no remembered sites.
- Network: `HTTPS_PROXY`/`HTTP_PROXY` unset for the server and the client (direct). The pages were loaded by Chrome itself, on whatever network Chrome uses; Octocrawl fetched nothing.
- Chrome: Howard's own Google Chrome 156.0.8078.81, remote debugging on through `chrome://inspect`, port 9222. Howard sat at Chrome, clicked what appeared and counted Chrome's "Allow remote debugging?" dialogs.
- Fixture: a throwaway local site on `127.0.0.1:8796` (pages `/a` to `/g`), not in the repository. Second site: `quotes.toscrape.com`.
- Requests: `POST /v1/scrape` and `POST /v1/batches` with `lane: "my-browser"`, from a scratch script, one after the other.
- Measured by the session: the server's `my_browser_approval` log (Octocrawl's own allow page), its TCP connections to `127.0.0.1:9222` sampled with `lsof` every 0.5 s (rounds 1 and 2, the server process only) and about every 0.1 s (round 3, every process), and in round 3 every WebSocket the server created (a `--import` preload that logs `new WebSocket` with its stack). Measured by Howard: Chrome's dialogs.

## What this run shows

- A2: one server read two pages of one site and ran two two-site batches over one connection, and Chrome asked once (round 1). The engine before A2 connects once per read, which the integration test measured as 3 connections for two reads and a batch; a real-Chrome run of that older engine was not done here.
- A1: a site allowed once is not asked for again, in later scrapes, in a later batch, and after a server restart. A batch's page lists only the site not allowed before. `octocrawl login revoke` makes the next read ask again, on the same connection, with no Chrome dialog.
- A server restart connects again, and Chrome asks again, as documented.

## Not explained

- After the first restart (s6) Howard counted two Chrome dialogs for what the 0.5 s sampling of the server process showed as one connection. After the second restart (s7) he counted one, and the finer measurement showed one WebSocket and one TCP connection, from any process. Whether s6 opened a second, short connection that the 0.5 s sampling missed, another process connected then, or Chrome asked twice for one connection is unknown. The code calls `connect` once per `openUserChrome`, with no retry.

## Limits

One person, one machine, one Chrome profile, a local fixture and one public site. No site behind a login was read, so this counts clicks, not whether a signed-in page was read as the person. Chrome's dialogs were counted by Howard, per round, not timed.
