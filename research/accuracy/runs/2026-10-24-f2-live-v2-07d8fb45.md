## How a live page is scored, and page drift

Unchanged from #698 and K1 window 1 ([2026-10-21-k1-w1-live-v2-322de68e.md](2026-10-21-k1-w1-live-v2-322de68e.md)):
- `sameSource` is dropped, because a live page never has the sealed capture's `rawSha256`.
- Every other check is kept under the scorer's own rule. Unit, date and period are not scored where the gold leaves them unknown.
- **Accepted:** every required field is correct, with no duplicates and nothing fabricated.
- **False success:** the answer claimed success and was not accepted. For Octocrawl, a claim is status `success` with a verify that did not fail. Firecrawl is sent no verify, so its claim is status `success`.

**Drift.** The gold is from 2026-10-20 captures, and the live pages have changed since then. A changed value scores as wrong for every arm alike. The drift is not isolated, the same as in K1 and #698. It is bounded in two ways:
- **The arms ran on the same day, interleaved per case,** so drift affects all three alike. The comparison between arms is the result. The absolute counts are not comparable with the frozen-capture numbers.
- **The gold marks 60 of the 294 required fields as other than `static`.** The table splits by that mark. List records marked `static` also move when new items come first, as K1 found.

**Against #698 the drift is not held fixed.** The two runs are a day apart and at a different time of day (05:20 UTC against 17:24 UTC), so a change between them can be the engine (#700), the page, the access path or, for the model and Firecrawl arms, the model's answer. Where this record names a cause, it says what it was read from.

All 42 cases stay in every denominator, including blocked, failed and changed pages.

## What this does not measure

- **Repetition:** one run per arm, so run-to-run variance is not measured, for the model, for Firecrawl's LLM or for the live pages. V41 (Haiku) and V04, V09 and V38 (Firecrawl) changed between this run and #698 on what looks like the same page; two runs cannot say how often that happens.
- **Drift against #698:** not isolated, and the time of day differs (V32). The three-arm comparison within this run is the result.
- **Effort and models:** the default `low` effort only, and Haiku only.
- **The list path with a model:** the model fallback is still not called when an `itemSelector` is set, so this run says nothing about a model on the 19 list/table cases.
- **Access findings, reported and not investigated here:**
  - V33: Octocrawl reported status `success` on Fastly's "Client Challenge" page, which is a block page, and ran a model call on it. Its verify failed, so it is not a false success under the live rule, but the page status is wrong.
  - V18: the Haiku arm's HTTP lane ran out the whole 120 s timeout, where the off arm read the page in 2.5 s. One occurrence; the cause is not established.
