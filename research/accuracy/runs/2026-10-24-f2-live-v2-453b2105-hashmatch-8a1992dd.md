## The bug

The same-day reference `sameday-v2-2026-10-24` was annotated on #701's off-arm (`standard`) sources, fetched 05:20–05:36 UTC. #705 ran 09:01–09:16 UTC and fetched new pages. The scorer still took the reference to be "this arm's own source" for `standard` (the reference arm) and `model` (the agreeing copy), because the names matched. On V34 (x-rates) the rates moved between the two fetches (`0.892538` → `0.892550` and two more). Against the reference, both Octocrawl arms' rates were wrong, so the scorer labelled the false success `extraction`. Against the page each arm actually read, all six fields match.

## The change (`live_rescore.py`, `8a1992dd`)

- **Match by hash, not name.** A new `page_refs` matches each arm's answer to an annotated page by `response.evidenceRecord.rawSha256`, which `--keep-html` keeps. An arm is on the reference source only when that hash equals the reference source's, or a copy from the reference's run that the agreement check covers (as before for #701's `model` copies).
- **`--own-pages <dir>` (repeatable).** These are annotations of the pages a later run read, shaped like the same-day set: `cases/<ID>/gold.json` carrying the page's `rawSha256`, or `block-error.json` where the block did not run. An arm whose page one of them covers is labelled against that annotation. A value that moved between the reference's fetch and the arm's is therefore `drift` when the answer matches its own page, and `extraction` when it does not.
- **No hash, or an unmatched hash.** The arm is never on its own source, so the "this arm's own source" evidence is never used for it. It is labelled under the rules for another arm's source, against a page this run read when one is annotated (as Firecrawl always was). If no page this run read is annotated, the reference is a different fetch from all of them. Then only `drift` (correct against the reference) and `schema_scope` can be shown, and every other failing field is `unknown`. If the annotated pages of this run disagree on a field's value, that field is treated like a fast-changing one (only the arm's own page can show it).
- **Scores do not change.** Required counts, acceptance and false successes are still scored against the reference set. The change affects only the cause labels.
- **Failing first.** `SourceByHash` in `test_live_rescore.py` has 5 tests. On `origin/main` (`5c1db14e`, with the test's call trimmed to the old signature), 4 of them fail with `'extraction' != …`. The fifth, an arm that read the reference bytes, passes on both versions as a regression guard. All 5 pass at `8a1992dd`.

## Limits

- The own-page annotations come from the set's blocks, audited against the bytes. Nobody has spot-checked them. They label false successes and are not a score.
- When both Octocrawl arms' pages are annotated, an arm without a source (Firecrawl) is labelled against the first of them in arm order (`model`). Here the two agree on every value, so the choice does not matter in this run.
- An arm without a source is labelled against a page this run read, which assumes it fetched in the same minutes. Fast-changing fields are guarded as before. In #705 Firecrawl ran interleaved per case, as in #701 (V29: 09:10:52–09:11:10; V34: 09:12:07–09:12:15).
