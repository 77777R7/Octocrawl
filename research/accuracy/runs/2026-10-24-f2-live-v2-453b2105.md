## What this does not measure

- **Drift.** The gold is from 2026-10-20, and its absolute counts mix engine and page change, as in #701. The same-day reference removes most of that, but it was taken about 3 h 40 min before this run: on V29 and V34 (14 of the 164 annotated values) the page this run read differs from it, so their same-day scores are against an older page, in every arm. The arms ran interleaved per case, so drift within this run affects all three alike. Against #701 the drift is not held fixed (the runs are about 3 h 40 min apart).
- **Cause labels on a run after the reference.** `live_rescore.py` treats an arm named `standard` as the reference's own source and `model` as agreeing with it. On this run those arms fetched new pages, so its "this arm's own source" evidence is the 05:20 page, not theirs. That changed one label (V34, read above from the arms' own kept sources). Every other Octocrawl label was checked against the own-source run: the 20 other annotated cases are identical value for value. The scorer is not changed here.
- **Repetition:** one run per arm. V33 (access), V37 (Haiku) and V09, V15, V21, V38 (Firecrawl) changed between this run and #701; two runs cannot say how often.
- **Effort and models:** default `low` effort, Haiku only.
- **The list path with a model:** still not called when an `itemSelector` is set.
- **Access findings, reported and not investigated here:**
  - V18: the Haiku arm's HTTP lane ran out the whole 120 s again (lanes `http`, `browser_local`), and the off arm, right after it, read the page in 0.8 s over HTTP. In both runs the Haiku arm went first on V18 (the order rotates by case), so the slow fetch may belong to the first fetch of the case rather than to the arm. Two occurrences; the cause is not established.
  - V33: the Haiku arm got the real page this time, so #701's finding (status `success` on Fastly's challenge page) did not recur and was not retested.
