## Cause labels

`live_rescore.py` labels each failing required field of a false success against the gold, then gives the case the first label in the order access, extraction, unknown, schema_scope, drift. The rules are in its docstring and have synthetic controls in `test_live_rescore.py`:

- **drift:** the answer is correct against the same-day annotation.
- **schema_scope:** what still fails is a unit, date or period check that the perfect answer to the request (every requested property exactly as the reference states it) fails too.
- **extraction:** the run-day page stated a value the answer did not deliver. Evidence is one of: the same-day annotation of this arm's own source, or of a source that agrees with it; a value unchanged since the gold; another field of the same record that the answer matches against the same-day annotation; or, without a same-day annotation, the gold value returned by another arm in this run. Duplicate records also count. For fields that can change within minutes (`live`, `hourly`, `volatile`), only the arm's own source counts as evidence.
- **access:** the arm's own kept page does not carry the task structure. No false success has this label: the one such page, V33 for the Haiku arm, was not a success claim.
- **unknown:** none of the above can be shown, including a right value whose unit is given as the page writes it (`€`) where the gold normalises it (`EUR`).

## What this does not show

- **The spot check is pending.** Until Howard's check of the 36 sampled fields is recorded, the same-day annotation is an engineering source check by the same session that wrote the labels.
- **Six cases in scope have no same-day annotation** (V15, V16, V17, V31, V32, V35). Their scores and causes rest on the 2026-10-20 gold, so they understate every arm where those pages changed, and most of Firecrawl's `unknown` labels are there. Annotating them needs new rules written for the run-day pages.
- **Firecrawl's page is not kept.** Its reference is the page Octocrawl read at the same moment. That is why a changed value counts as Firecrawl's extraction error only with the evidence listed above, and fast-changing fields of Firecrawl stay `unknown`.
- **Cause labels are rules, not review.** They are read from the scored rows, the request schema and the kept sources. No one has checked the labels by hand beyond the examples in this record.
- **Only the json mapping is labelled.** Markdown scores are unchanged from #701 and have no same-day column.
- **This is one run.** Variance between runs, for the pages, the model and Firecrawl, is not measured.
