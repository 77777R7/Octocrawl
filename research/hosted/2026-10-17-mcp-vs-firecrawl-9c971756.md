# Hosted Octocrawl MCP and Firecrawl MCP on three tasks, 2026-10-17

A rerun of a small comparison Howard made on 2026-10-16 between the hosted Octocrawl MCP (keyless) and Firecrawl's MCP (signed in with OAuth). That first run had two problems. Octocrawl was keyless and Firecrawl was signed in, so the two sides were not run under the same conditions. Its commands and times were also not recorded. This run adds Octocrawl signed in through `/mcp-oauth` (ROADMAP PH item 6) and Firecrawl's keyless endpoint, all inside two minutes. **Firecrawl signed in was not measured**: its OAuth MCP was not connected in the session that ran this, so that column is null. The 2026-10-16 result is not carried over into it.

Three tasks, the same as the first run's:

1. Scrape `https://example.com`.
2. Scrape `https://quotes.toscrape.com/js/`, whose ten quotes are filled in by JavaScript.
3. Map `https://quotes.toscrape.com/` (limit 100).

## How it was run

- **Time**: 2026-10-16 16:21:53–16:23:02Z (2026-10-17 in Howard's local time).
- **Machine**: Howard's Mac, from a Claude Code session in the Claude desktop app.
- **Proxy**:
  - The curl calls were proxied (`HTTPS_PROXY=http://127.0.0.1:7890`).
  - The signed-in Octocrawl calls went through the session's MCP client. Whether that traffic went through the proxy was not checked.
- **Octocrawl server**: `octocrawl-api` revision `octocrawl-api-oauthrs-9c97175` (tag `h17oauthrs`, from main `9c971756`). Every Octocrawl answer below names extractor commit `9c971756`.
- **Repository**: main `9db14102` when the run was made.
- **Firecrawl server**: `https://mcp.firecrawl.dev/v2/mcp`, which reported `serverInfo` `firecrawl-fastmcp` 3.30.2. This is newer than the pinned parity comparison (firecrawl-mcp 3.25.5 / firecrawl-js v4.42.0). This run is a product check, not a parity record.
- **No caching on either side**: Octocrawl's `maxAge` defaults to 0, and Firecrawl was sent `maxAge: 0`.

### Octocrawl, signed in

- **Configuration**: `claude mcp add --transport http octocrawl-oauth https://mcp.octocrawl.dev/mcp-oauth`, signed in with Howard's account (see `2026-10-16-mcp-oauth-clients-adee17f2.md`).
- **Tool calls**: each was labelled `integration: "mcp-compare-2026-10-17"`.
  - `scrape {url: "https://example.com"}`
  - `scrape {url: "https://quotes.toscrape.com/js/"}`
  - `map {url: "https://quotes.toscrape.com/", limit: 100}`

### Octocrawl, keyless

These are JSON-RPC calls with curl to `https://mcp.octocrawl.dev/mcp`, with no Authorization header:

- `initialize`, then `notifications/initialized` with the returned `mcp-session-id`.
- `tools/call` with the same three arguments as above.

### Firecrawl, keyless

These are JSON-RPC calls with curl to `https://mcp.firecrawl.dev/v2/mcp`, with no Authorization header. It returned no `mcp-session-id`.

- `initialize`, `notifications/initialized` and `tools/list`.
- `tools/call firecrawl_scrape {url, formats: ["markdown"], maxAge: 0}` for the two scrape URLs.
- The answers came as `text/event-stream`. The `data:` line was parsed.
- Quotes were counted as the number of `“` characters in the returned Markdown, on both sides.

## Results

| Task | Octocrawl signed in (`/mcp-oauth`) | Octocrawl keyless (`/mcp`) | Firecrawl keyless (`/v2/mcp`) | Firecrawl signed in |
| --- | --- | --- | --- | --- |
| Tools listed | `scrape`, `map`, `scrape_product` | `scrape`, `map` | `firecrawl_scrape`, `firecrawl_search`, `firecrawl_parse` | null |
| example.com | success, lane `http`, 56 ms | success, lane `http`, 44 ms | 200, 1 credit, 1.9 s round trip; the Markdown also holds the page's translations | null |
| quotes.toscrape.com/js/ | **success**, lane `browser_local` (`channelsTried` `http`, `browser_local`), 10 quotes, 9.0 s wall time | failed, `empty_unverified`, lane `http`, 0 quotes, 681 ms | 200, 10 quotes, 1 credit, 2.1 s round trip | null |
| map quotes.toscrape.com | completed, 47 links returned, 3 refused | completed, 47 links returned, 3 refused | no map tool on the keyless endpoint | null |

Octocrawl's times are the answer's `usage.wallMs`, measured on the server. Firecrawl's are the curl round trip from the Mac through the proxy, so the two are not the same measure.

The Octocrawl credits these calls cost were not read. They are unknown, not zero.

The keyless Octocrawl answer on the JS page names the reason in `agentHints`: "hosted Octocrawl reads over HTTP alone without a key, so the browser lane did not run; a key opens it …". This is the hint added in #531.

## What this shows

- Signed in through OAuth, the hosted Octocrawl MCP now completes all three tasks. The JS page that failed in the first run is read on the browser lane.
- Keyless, the hosted Octocrawl MCP still fails the JS page by design: keyless calls use the HTTP lane only.
- Keyless, Firecrawl renders the JS page, about 2 s end to end against Octocrawl's 9 s signed in. The two times are measured differently (see Results).
- Keyless Firecrawl lists no map tool.
- Not shown here:
  - how signed-in Firecrawl does on these tasks, since that column was not measured;
  - anything about speed, stability or cost at scale, since there was one call per cell.
