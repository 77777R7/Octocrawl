# MCP client tasks, E2 round after W7–W10: 0.6.0 against 0.7.0 (2026-10-18)

The E2 fixed-task round of [docs/mcp-client-ux-tasks.md](../../docs/mcp-client-ux-tasks.md). It runs Claude Code and Codex CLI headless against `@octocrawl/mcp` 0.6.0, the baseline, and 0.7.0, which holds W7–W10. No baseline round had been run before, so both sides were run here, on the same day and against the same API.

## What ran

- **Source commit:** f29559c8 (main, release 0.7.0). The local API was started from it with `npm run api` on port 8787, and the fixture server with `FIXTURE_PORT=8796 npm run serve -w @w2l/fixtures`.
- **MCP servers:**
  - Local: `@octocrawl/mcp` 0.6.0 and 0.7.0 as published on npm, each installed in its own directory and run as `node …/dist/stdio.js --base-url <url>`.
  - Hosted (task g only): the tag URLs `h20v060` (`octocrawl-api-v060-67d01484`, 0.6.0) and `h23v070` (`octocrawl-api-v070-f29559c`, 0.7.0), keyless.
- **Clients:**
  - Claude Code 2.1.301 (`claude -p`, model claude-opus-5-5), run with:
    - `--strict-mcp-config` and Octocrawl as the only MCP server;
    - `--allowedTools mcp__octocrawl,Read` and `--disallowedTools WebFetch,WebSearch,Bash`.
  - Codex CLI 0.162.1 (`codex exec --json --ephemeral`, model gpt-6.1-sol, reasoning high), run with:
    - a separate `CODEX_HOME` holding only the model settings, `approval_policy = "never"` and `sandbox_mode = "read-only"`;
    - Octocrawl added with `-c` and `default_tools_approval_mode = "approve"`.
  - Cursor and OpenCode: **not run**. VS Code Copilot, claude.ai and ChatGPT: **not run**.
- **Harness:** [2026-10-18-mcp-e2-w7-w10/harness.mjs](2026-10-18-mcp-e2-w7-w10/harness.mjs).
  - Command: `node harness.mjs claude,codex v060,v070 a,b,c,d,e,f,g,h,i,j,k,l 3 4`, with 4 runs at a time. A first pass of the same command on v070 tasks a, g, h and j checked the harness. Its seven valid runs are part of the 144. The eighth, `codex-v070-g-1`, failed on a harness config error and was run again.
  - Scoring: the checks were tightened after the run, then the stored output was scored again with `node harness.mjs rescore` (see "Scoring corrections").
  - Every run's record: [2026-10-18-mcp-e2-w7-w10/runs.jsonl](2026-10-18-mcp-e2-w7-w10/runs.jsonl), with answers cut to 4,000 characters. The raw transcripts (13 MB) were not kept in the repository.
- **Proxy:** the local API reached real sites through the shell's `HTTPS_PROXY` (127.0.0.1:7890), so real-site reads were **proxied**. Loopback was direct. The clients ran with the proxy variables removed.
- **Runs:** 12 tasks × 3 repetitions × 2 clients × 2 versions = 144. All 144 ran to an answer. 8 of them are counted invalid, for the reasons below, and stay in the denominator of "Runs".

## What the runs show

- **Claude Code needed far fewer tool-search calls with 0.7.0.**
  - Count: 41 ToolSearch calls with 0.6.0 (3 to 7 in every task), against 9 with 0.7.0 (only in c, d and i).
  - Why: 0.7.0 marks scrape and map `anthropic/alwaysLoad` (W7.5), so the tasks that start with scrape or map no longer search for the tool first.
  - Duration: the median run went from 32 s to 27 s.
  - This is the one client-side change this round measured directly.
- **Large results now stay within the budget.** With 0.6.0, Claude Code saved oversized results to a file and kept a short note in the transcript: for c and k the median transcript result was 4,403 and 3,445 characters. With 0.7.0 the same tasks came back inline (164,086 over 8 calls for c; 60,716 for k). The pass rate was 3/3 either way, so this round shows the budget changes how results arrive, not whether Claude Code succeeds.
- **Codex misses do not come from Octocrawl's tools.**
  - Most come from the Codex setup. It loaded the person's global `ego-browser` skill and tried a browser and `curl` first (shell calls in 11 of the 12 tasks; none in i). Its read-only sandbox has no network, so those failed.
  - It then answered several reading tasks from memory: 7 false successes with 0.6.0, 5 with 0.7.0, all without a completed Octocrawl call. b, c and f are well-known pages.
  - The difference between 23/33 and 25/33 is two runs, within this noise. **This round does not show that 0.7.0 is better or worse for Codex.**
- **h: Codex never passes on the instruction.** Both versions return `api_unreachable: no Octocrawl API answered at http://127.0.0.1:8799; start it with npx octocrawl serve, or set W2L_API_URL` as an isError result. Codex read it in every run (0/3 both versions) but asked the person to paste the page instead of passing on the `npx octocrawl serve` instruction. Claude Code passed it on every time.
- **d: no duplicate crawl after the 504.** Both clients sent an `idempotencyKey` on the first crawl start and, after the 504, got the same task back (`replayed`). The Claude 0.6.0 runs started a second crawl only after changing the options (adding `crawlEntireDomain`, since the first crawl stayed in `/crawl/listing`'s subtree). The 0.7.0 runs set the scope on the first call.
- **Unchanged and passing in every valid run of both versions:** a, e, i, j and l in both clients, and d after the scoring correction.
- **Evidence:** only 3 answers, all from Claude with 0.7.0, cited finalUrl or the Evidence Record without being asked.

## Scoring corrections

The first scoring was too strict in three places, found by reading the answers. All three were fixed before the totals above, and every run was scored again from its stored output:

- **i:** answers saying `not_found` or "doesn't recognise" now count as reporting the id unknown.
- **l:** "verification screen" and "Just a moment" now count as reporting the block.
- **d:** a second crawl with different options is a new crawl, not a duplicate.

The 0-call rule for reading tasks was added in the same pass.

## Not measured, or not run

- **Confirmation prompts:** the interactive sample (3 tasks per client) was **not run**. What the headless runs do show is that a local scrape on 0.6.0 and 0.7.0 is not annotated read-only, so Codex with its default `auto` approval asks for it, and in `exec` with `approval_policy = "never"` refuses it. This is why the round sets `default_tools_approval_mode = "approve"`. W10's `--read-only` mode was **not run** here.
- **Tool-definition tokens** (Claude Code `/context`): **not measured**. E1 records the tools/list sizes (local 49,962 characters with 0.7.0).
- **Clients:** Cursor, OpenCode, VS Code Copilot, claude.ai and ChatGPT were **not run**.
- **Hosted task g** has only 2 valid runs per Claude version and none for Codex, because of the keyless allowance and Codex's app connector. A run with a key or OAuth would fix both.
- **Cost:** the Claude Code runs reported $24.75 in all (72 runs). Codex reports tokens, not cost.
