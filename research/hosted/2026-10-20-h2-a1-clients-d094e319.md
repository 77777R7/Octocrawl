## What the run showed besides

- **Codex asks before `batch_scrape`.**
  - In the first Codex run, the call failed with "MCP tool call requires approval, but approval policy is never", and no job started; the account's list shows none.
  - With `mcp_servers.octo_a1.default_tools_approval_mode="approve"`, the run above passed.
  - Starting a job is not read-only, so Codex asking is expected. The connect page now says so.
- **Two earlier Codex attempts never ran.** The first used `timeout`, which macOS lacks (exit 127). The second waited on stdin ("Reading additional input from stdin...") until it was stopped; `< /dev/null` fixed it. Both were runner mistakes, not product ones.
- **Job items carry `usage` and the full `trace` over hosted MCP.** A hosted scrape leaves these out. `get_crawl_pages` says pages omit the trace unless `debug` is set, but they did not. This is task M8.
- **The hosted `batch_scrape` schema is wider than what hosted takes.** It lists `mode: authed`, `maxFileBytes` up to 524,288,000, and a description that mentions `appendToId`; the REST gate refuses or lowers these. This is task M9.
