## Deviations from the plan, stated

- The plan's example text for the 404 entry (`The server answered 404; the content is that response, not the requested page.`) is a warning no lane on `main` emits: an error-status page carries no warning, and the http_error sentence is an agent hint on items whose page was kept. The errors report follows the plan's rule for that case, `<status>: <code>` with the HTTP status (`failed: http_error (HTTP 404)`), and the robots refusal names its rule from the `robots_disallowed` event. The fixture test asserts these two strings.
- Check A's pages were all `success`; the `partial` / `low_confidence_extraction` outcome of the 2026-09-30 rerun did not occur in this run.
- The item for `https://example.com` is recorded under `https://example.com/`, the URL as the frontier normalises it; the request's spelling is in the task's `urls`.
- The checks ran through the API started from source with `--import tsx` (the task's local-API command) rather than `packages/api/dist/cli.js`; the same code, built first.
