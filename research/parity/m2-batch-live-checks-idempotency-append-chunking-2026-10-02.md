## Deviations from the plan, stated

- The plan's requests name port 8787; this worktree's API runs on 8807 (another session's API owns 8787), and the requests above went there.
- The record cannot count robots.txt requests from the items: the sandbox serves no robots.txt (`robots_checked` says `no_robots` on every item, `robotsSha256 null`), and the event carries no timing. The robots cache looks a host up once per API process and answers from memory after that; the one lookup is the cache's contract, not a measurement of this run.
- `.w2l/api/idempotency.sqlite` existed before the API started (file birth 21:00:33 local): `npm test` ran on this tree first, and one test engine is created without `taskRoot` (`packages/api/test/app.test.ts`, line 1072), so it opens the index at the default root `.w2l/api`, as such an engine has always opened `section-b-control.sqlite` there (born 20:04 local, before any API ran in this worktree). The API reused the file; the keys of this run were not in it before the run (the first POST of A was `fresh`: it started the job). An earlier wording of this note named `packages/mcp/test/fixture-scrape.test.ts`, which passes a temporary root; corrected in the commit after the record's, the findings unchanged.
- The cancelled batch of B was "created from one page" as a one-URL batch whose page was never fetched: the cancel landed 4 ms after the 202, before the first request.
- The checks ran through the API started from `packages/api/dist/cli.js`, the build of the committed source, as the task's command says (the group's first batch ran `--import tsx` from source; the same code either way).
- No real site of the frozen test set is part of this batch's checks; the three features are exercised on the toscrape sandbox alone, as planned.

Known leftovers, named here: the idempotency index is per task root and per API process, as the batch contract is (one process per root); it tells one process's submissions apart and is not a lock between processes. A replayed append answers the 202 as it was recorded, with `requested` as at that append. The `w2l` CLIs have no flag for `idempotencyKey` or `appendToId`. Firecrawl's `/v2/batch/scrape`, `appendToId` and its idempotency header included, has no `/fc` mapping yet; `/fc/v1/crawl` honours the header. `batchScrapeChunked` restores the submission order by each item's `url`, the submitted URL's WHATWG href; an item the API records under another spelling keeps its recorded place after the matched ones. The engine's post-run relaunch fires only for a completed batch whose latest attempt hit no budget and still has URLs without a step; a hosted batch cut by `batchMaxWallMs` runs again only when a new append asks.
