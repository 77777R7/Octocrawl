## Deviations from the plan, stated

- E1: the arXiv abstract page states no Dublin Core or article tag (its bibliographic data is in `citation_*` tags), and neither does GOV.UK (E2), so on the real sites the check passes vacuously: nothing is invented, and the fields equal the tags. The positive mapping of all 14 fields rests on the fixture (E3) and on `packages/extract-tf/test/metadata.test.ts`. No frozen row is known to carry `dc.*` or `article:*` tags.
- E2 ran a fresh GOV.UK fetch where the plan wanted an offline cross-check over `.w2l/parity-live-batch/08-govuk-raw.html`: that capture lives in another worktree's git-ignored `.w2l/` and is not present here. The fresh page gives the four og fields the plan expected and no `ogDescription`.
- F1: the IMF outcome was a 403 on the http rung followed by a rendered page on the browser rung, not a block, a stamped quality hop or a kept shell. The browser rung's answer is a thin listing (226 tokens, extraction confidence 0) reported as `success`, with no warning, because the quality signals are the http rung's alone (finding 1).
- G1 was not in the plan; it was added so the record shows the `low_content_yield` warning and the `warning` string on a real page, after F1 to F3 produced none. It used a sandbox of the frozen test set under `fastMode`, one fetch.
- The low-yield message of a `failed` / `empty_unverified` shell reads `found no main content at confidence C` where the plan wrote `extracted N tokens at confidence C`: such a result has no main-content token count (`usage.contentTokens` is null), and inventing 0 would be a count the lane never made. A thin `success` carries the plan's wording with the http rung's `quality_low_yield` figures.

## What the run also showed

1. The browser rung raises no quality signal: `quality_low_yield` and `quality_client_rendered` are the http rung's events, so a page the browser rung renders into a thin listing (F1: 226 tokens at extraction confidence 0, the page's navigation links while the data is drawn by script) is `success` with no `low_content_yield` and no hint. Pre-existing, outside this batch; a browser-rung quality signal would be a change to the ladder's escalation model and is left as a follow-up.
2. Apple's page carries 49 `data:` URIs in image attributes (lazy-loading placeholders); the images collector counts and drops them (`dataUrisDropped: 49`), and the page's 170 `<picture>` elements give the srcset-candidate case the plan asked for on the fallback row.
3. Every real site of this run answered the http rung except IMF; no check reached the browser rung's images or attributes path, which `packages/bench/test/pageOptions.test.ts` covers on a local page.
