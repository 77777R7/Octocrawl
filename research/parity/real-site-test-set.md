# W2L real-site test set (proposal)

**Every URL below is unverified from this environment.** I only used WebSearch. No page, robots.txt or terms page was fetched, so all robots, terms and content notes are leads to re-check when the run starts.

**How the set was scoped**
- I left out every host in the seed user's manifests. `research/coos-pilot/coos-manifest.v1.json` covers 39 hosts, including sec.gov, aka.ms and the data-centre operators. `research/datacenter-partner-pilot-manifest.v1.json` covers eia.gov, census.gov, www2.census.gov, energy.gov and eta-publications.lbl.gov.
- OCR is out of scope. The only PDF (#36) has a text layer.
- **What the current build accepts:**
  - Formats are limited to `markdown`, `links` and `json` (`packages/contracts/src/api.ts:179-204`).
  - Routes: `/v1/scrape`, `/v1/batches`, `/v1/crawl`, `/fc/v1/*` and `/v1/monitors`.
  - For feature ids W2L doesn't have yet, the expected result today is an explicit 400. Record that as "missing". A silently ignored option counts as a failure.
- **Outcome words to check.** Statuses: `success`, `partial`, `empty_verified`, `blocked`, `failed`. Reasons: `http_error`, `policy_denied`, `timeout`, `tls_error`, `dns_error`, `connection_error`, `body_too_large`, `unsupported_content_type`.
- **Run rules (AGENTS.md):**
  - Freeze the list before the first run.
  - Keep every failed or blocked URL in the denominator, and don't swap URLs after freezing.
  - Record the command and source commit.
  - Keep outputs under `.w2l/`.
