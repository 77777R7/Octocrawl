## What failed, and why

- **AC01, AC05, AC07, AC08, AC09: the steps passed, the page was `failed` / `empty_unverified`.** Every step's trace event is `ok` and the steps did what they were for (AC07: 6 products, then 12). The extractor then found no main content on these list pages (confidence 0), with the default `onlyMainContent: true`; with `onlyMainContent: false` the same steps pass (AC13, AC14, AC16 to AC18). The verdict is the extractor's, not the steps': a list of records is not an article. It matters for the interaction phase's list-record extraction (I4).
- **AC05: 20 quotes, not 30.** `scroll` moves one screen, as the step is specified, and three screens of quotes.toscrape.com/scroll loaded one more page of ten. The audit expected 30. Scrolling until a list stops growing is a separate step (I3).
- **AC06: `#2015` is not a valid CSS selector** (an id selector cannot start with a digit), and the click failed as `action_error` with Chromium's message, the page kept as it stood. AC15 names the link as `[id="2015"]`.
- **AC02, AC03, AC04 (the-internet.herokuapp.com): not run as far as their steps.** Proxied, the browser's navigation passed its 20 s limit (`navigate_failed`, then `failed` / `timeout`) in runs 1 and 2, while curl through the same proxy answered in about a second. Direct (run 3), robots.txt timed out (`policy_denied`, `unreachable: timeout`) and curl to the site timed out after 20 s too. So these three checks (a fixed wait, a wait for a hidden element to be shown, a key press) are not shown live; the integration tests cover them on a local page (`packages/bench/test/browserActions.integration.test.ts`).
- **AC12: `markdownIncludes "Example Domain"` failed** because the page's only heading becomes the title, not Markdown, which the check did not allow for. The rest of AC12 passed: `failed` / `action_failed`, `actions.failed` `{index: 1, code: selector_not_found}`, one scrape before the failure and none after, the page's text kept.
