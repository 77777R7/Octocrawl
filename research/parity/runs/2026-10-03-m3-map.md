## Findings

1. **Limit and deadline disagree (reproduced, unfixed).** This is the batch-A review's minor issue. When page links alone fill `limit`, the sitemap load still gets `maxUrls: 0`, reads the index and a whole child, and only counts overLimit. Fixture F4 showed the cost: two links in hand, a 2 s wait on a stalled child, then `status: "partial"` with `stoppedBy: "limit"`, `map_timeout` and `sitemap_unreadable`. The plan says the load "returns at once" in this case, and status and stoppedBy should agree. On a real site the same path cost MP17 a read of MDN's en-us child (14,820 entries) for overLimit 278.
2. **python.org (MP13/MP14) is still blocked outside the map.** The http lane does not inflate the gzip body www.python.org sends unasked, and `/sitemap.xml` redirects to itself for W2L's identity headers. The map reports both honestly (`start_page_unreadable`, `sitemap_unreadable`, partial). The `start_page_client_rendered` warning on that empty gzip body is misleading, since the page is compressed, not script-filled. The follow-up belongs to the http lane: decode a Content-Encoding it did not request.
3. **MP06 did not abort an in-flight file this time.** gov.uk's `sitemap_2.xml` finished just before the 3 s deadline, so the file list ends with unread children rather than an `unreadable/timeout` record; the plan accepts either. The aborted in-flight file was shown on the fixture (F1). The deadline overran by 97 ms here (elapsedMs 3,097) and by 3 ms on the fixture.
4. **The `map_timeout` count leaves out the aborted file.** In F1 the message says `0 sitemap files were not read` while `slow.xml` was aborted mid-read. The aborted file is named in the separate `sitemap_unreadable` warning, so nothing is hidden, but a reader of `map_timeout` alone would miss it.
5. **The robots part of MP09 was not exercised.** The first 500 gov.uk entries held no robots-disallowed URL (`refused.robots` 0), the same as on 8da3e73. Sitemap-entry robots refusal is shown only on the fixture (`/private/y`).
6. Not run live here, so it rests on unit and loopback tests: the robots host cap (more than 20 hosts), the hosted `browser_only` refusal and the hosted 429, the hosted MCP host's absence of `map`, and the SDK's `map()` / `getMap()`.
