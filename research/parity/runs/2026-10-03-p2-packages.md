Found and fixed during these checks and their review:
- `w2l-mcp` run through `node_modules/.bin`, which is how npx runs it, exited at once without serving. Its entry guard compared the symlink's path with the module's real path; it now compares real paths.
- The first SDK declaration bundle left imports of `./status.js`; the SDK now ships tsc's declarations with `@w2l/contracts`' beside them.
- The SDK did not export `EvidenceRecord`; it now does.
- The review found that in the one-file CLI bundle the API server's and the ladder CLI's own entry guards also matched, since every module shares the bundle's `import.meta.url`: run by its real path (as Windows and pnpm shims run it), `w2l --version` also started the ladder CLI and an API server on 8787 that never exited. npx's symlink had hidden it. The pack script now turns off every guard but the entry's, and the check runs the bin by its real path.
- The review found that `@w2l/mcp` declared twelve dependencies its bundle never imports (better-sqlite3, Playwright, ...), from the workspace closure; dependencies now come from what the bundle imports.
- Licences: the MIT SDK bundles `@w2l/contracts`, which had no licence of its own (so the root AGPL applied); contracts is now MIT, with its own LICENSE. `@w2l/mcp` said MIT in the repository while it is published as AGPL-3.0-only; its package.json and LICENSE now say AGPL.

Not shown:

A later npm that blocks such scripts would leave the CLI without its SQLite binding; the package READMEs say how to allow it.
- Windows, a clean macOS machine without Playwright's Chromium, and the browser lane from the installed CLI were not tried; the scrapes here answered on the http lane.
