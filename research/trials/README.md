# Octocrawl 非作者真实任务试用

请用 Octocrawl 尝试一个你自己正在做的数据获取任务，并保留成功和失败的结果。无需等待全部工程验收。

## 开始使用

1. 选一个你实际需要的任务：原始 URL、要取得的内容或字段，以及结果将用于什么。
2. 在你常用的 MCP 客户端，按[连接说明](https://octocrawl.dev/docs/connect-mcp/)添加远程地址 `https://mcp.octocrawl.dev/mcp`。默认无需账号或密钥。
3. 用自己的 URL 发起任务。需要找页面时先用 `map`，读取页面用 `scrape`。可以使用下面的提问模板。
4. 对照原网页检查交付内容，把实际操作、结果和遇到的问题填入[记录模板](TEMPLATE.md)。无法完成也请记录。

```text
我需要从 <我的 URL> 取得 <我要的内容或字段>，用于 <我的真实用途>。
请使用 Octocrawl 完成。保留实际响应、finalUrl 和 Evidence Record。
分别说明页面是否读取成功、配置检查是否通过，以及哪些要求还没有满足。
如果来源没有交付目标内容，保留失败原因，不换页面来冒充原任务完成。
```

无密钥入口提供 `scrape` 和 `map`，通过 HTTP 读取公开页面。需要浏览器的站点可能无法完成。
限额、登录、验证码、robots.txt 或来源本身没有数据，都应原样记录；不要为了完成试用购买服务。
需要本地能力时，连接说明也提供 local 入口；记录自己实际使用的包版本和安装时得到的帮助。

## 检查结果

- `status` 描述页面获取结果。`success` 本身不能证明目标任务完成。
- `verification.status: passed` 仅表示已配置检查通过；仍需人工核对主体、数值、单位、日期、记录对应及缺失。
- `failed` 时查看检查原因和 `readiness`。`not_requested` 或缺少 verification 时，任务没有经过契约检查。
- 对每个实际交付字段核对同次来源；无法核对就写“未知”。没有取得的数据不能填零，也不能从别的页面补齐后宣称原任务通过。

不要在记录中放密钥、Cookie、邮箱或其他个人信息。原始响应、截图和可能敏感的任务材料放在私有位置，记录中只写脱敏摘要和证据位置。
